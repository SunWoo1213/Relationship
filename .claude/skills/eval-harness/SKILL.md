# eval-harness — 평가 하네스

## 왜 이렇게 하는가

"그냥 GPT 부른 거 아니냐"에 대한 최종 반박이 여기서 나온다. 재현 가능한 수치와 베이스라인 비교, 트레이드오프 곡선이 결과 섹션의 핵심이다.

## 1. 데이터셋 스키마 (고정)

각 시나리오:
```json
{
  "id": "sc-001",
  "category": "promotion | pronoun | alias | normal | new_person",
  "utterances": ["오늘 김팀장이랑 또 부딪혔어", "..."],
  "mentions": [
    {"turn": 0, "surface": "김팀장", "gold_person_id": "p1"}
  ]
}
```
- 150건을 카테고리별 배분: 승진 호칭변경 / 지시대명사 / 별칭혼용 / 정상 / 신규 등록 판정(`new_person`).
- 호칭 변이를 **의도적으로** 포함한다.

## 2. 지표

| 지표 | 의미 |
|------|------|
| Precision/Recall/F1 | 인물 동일성 판별 전반 |
| **오병합률(False Merge Rate)** | 핵심 — 다른 사람을 같은 사람으로 묶은 비율 |
| 미검출률 | 같은 사람을 다른 사람으로 분리한 비율 |
| 이벤트·일정 추출 F1 | 구조화 추출 정확도 |
| 툴 호출 정확도 | 올바른 툴 선택 비율 |
| `ask_user_rate_by_kind` | ask_user 발생률을 `identity` / `new_person` / `schedule`로 분리 집계 — 정확도–마찰 트레이드오프 |
| `calibration` | `s_llm` 구간(0.1 단위)별 실제 정답률. 자기보고 확신도의 신뢰성 근거 |

**오병합률과 미검출률은 반드시 분리 측정.** 비대칭 비용 때문(오병합=신뢰 붕괴, 미검출=복구 가능).

## 3. 베이스라인 3종 + 제안 방식 (동일 데이터·동일 지표)

| 방식 | 구분 | 기대 |
|------|------|------|
| 문자열 완전 일치 | 베이스라인 1 | 낮음 |
| 임베딩 유사도 단독 | 베이스라인 2 | 중간 |
| LLM 단일 프롬프트 | 베이스라인 3 | 중간~높음 |
| 제안 4단계 하이브리드 | 제안 방식 | 높음 |

## 4. 트레이드오프 곡선 (하이라이트)

임계치는 두 개다(`T_merge`, `T_new`). 곡선의 **x축은 `T_merge` 하나로 고정**하고 **`T_new`는 0.3으로 고정**한다.

- x = `T_merge` ∈ {0.5, 0.55, …, 0.95}
- y = 오병합률 · `ask_user(identity)` 발생률 · 미검출률

**`T_merge`를 높이면 오병합↓ 질문↑ → UX↓.** (낮추면 더 낮은 확신도에서도 병합하므로 오병합이 는다.) 곡선에서 **운영 최적점**을 근거와 함께 제시한다.

## 5. 재현성 / 비용

- 결과를 `reports/metrics.json`에 저장하고 재사용한다(LLM 비용 절감).
- 개발 중에는 소형 모델·프롬프트 캐싱을 사용한다.
- 같은 입력 → 같은 수치. metrics.json만으로 `reports/eval.md`를 재생성할 수 있어야 한다.

## 산출물

- `data/scenarios/*.json` — 데이터셋
- `reports/metrics.json` — 원수치
- `reports/calibration.json` — `s_llm` 구간별 정답률 보정표
- `reports/cost_estimate.md` — 시나리오 1건당 토큰 실측과 전체 평가 비용 추정
- `reports/embed_pilot.md` — 임베딩 공급자 파일럿 결과(backend-agent 산출, 평가가 참조)
- `reports/eval.md` — 표·곡선·해석·최적점

## 품질 체크

- [ ] 150건이 카테고리별로 배분되었는가 (`new_person` 포함)
- [ ] 오병합률/미검출률이 분리 측정되는가
- [ ] 베이스라인 3종 + 제안 방식이 동일 조건으로 비교되는가
- [ ] 트레이드오프 곡선의 x축이 `T_merge`이고 `T_new`가 0.3으로 고정되었는가
- [ ] 곡선에 운영 임계치 근거가 있는가
- [ ] ask_user 발생률이 kind별로 분리 집계되는가
- [ ] 보정표가 산출되었는가
- [ ] metrics.json으로 리포트 재생성이 되는가
