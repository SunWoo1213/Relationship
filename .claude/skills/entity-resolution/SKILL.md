# entity-resolution — 엔티티 해석 4단계

## 왜 이렇게 하는가 (먼저 이해)

한국어는 사람을 이름으로 지칭하지 않는다. 같은 사람이 `팀장 → 김팀장 → 우리 팀장님 → 그 사람 → 걔 → 부장님(승진 후) → 김선배`로 등장한다. 이를 하나로 묶는 것이 시스템 성능을 좌우한다.

**LLM 단일 호출로 하면 안 되는 이유:**
- 인물이 늘면 전체를 프롬프트에 넣을 수 없다 → **1단계(후보검색) 필요**
- LLM은 위계·소속 제약을 자주 어긴다("팀장"과 "이모"를 혼동) → **2단계(규칙필터) 필요**
- 오병합 비용 ≫ 미검출 비용 → **4단계(안전장치) 필요**

## 절차 (반드시 4단계)

| 단계 | 방법 | 목적 |
|------|------|------|
| 1. 후보 검색 | **별칭 단위** 임베딩(`person_aliases.embedding`) top-K(K=10) → 인물별 max 유사도 | 전체를 프롬프트에 넣지 않음 |
| 2. 규칙 필터 | 한국어 호칭 사전 + 소속·위계 제약 | 명백히 다른 후보 배제 |
| 3. LLM 판정 | 대화 맥락 + 후보 정보 → `{matched_person_id \| null, s_llm, reason}` (구조화 출력) | 최종 판정 |
| 4. 안전장치 | 확신도가 `T_merge` 미만 → `ask_user` | 오병합 방지 |

인물당 벡터 하나(`person_embeddings`)는 쓰지 않는다. "김팀장"으로 만든 벡터 하나로는 "부장님"을 찾을 수 없다. 별칭이 쌓일수록 검색이 좋아지는 구조여야 한다.

## 확신도 산출

세 신호를 결합한다. 단일 신호에 의존하지 않는다.

| 신호 | 정의 | 가중치 |
|------|------|--------|
| `s_llm` | LLM이 **구조화 출력으로 직접 낸 0~1 확신도**. **로그 확률이 아니다**(Claude API가 제공하지 않는다) | 0.5 |
| `s_emb` | 후보 검색의 코사인 유사도(0~1 정규화) | 0.3 |
| `s_rule` | 규칙 필터 통과 항목 수 / 검사 항목 수(위계 일치·관계 태그 일치·호칭 사전 호환) | 0.2 |

```
confidence = 0.5·s_llm + 0.3·s_emb + 0.2·s_rule
```

가중치는 파일럿 평가에서 조정한다. `s_llm`은 자기보고 점수이므로 **보정표**가 필요하다: 파일럿 세트로 `s_llm` 구간(0.1 단위)별 실제 정답률을 산출해 `reports/calibration.json`에 저장한다. 이 표가 "자기보고 점수를 왜 믿을 수 있는가"의 근거다.

## 확신도 → 행동 분기 (임계치 2개)

초기값 `T_merge = 0.8`, `T_new = 0.3`. 파일럿 평가의 트레이드오프 곡선으로 확정한다.

| 구간 | 행동 |
|------|------|
| `confidence ≥ T_merge` | 기존 인물로 **연결** (`update_person`으로 별칭 누적) |
| `T_new ≤ confidence < T_merge` | `ask_user(kind="identity")` — "김팀장님 말씀이신가요? 승진하셨다면 반영할게요" |
| `confidence < T_new` | `ask_user(kind="new_person")` — "○○을 기억해둘까요?". 승인 시에만 `create_person` |

**확신도 低에서 자동 `create_person`을 하지 않는다.** 연예인·지나가는 언급이 인물 카드가 되는 것을 막는다.

## 승진/호칭 변경 처리 (데모 하이라이트)

"부장님이 또 그러시더라"처럼 위계가 바뀐 지칭은:
1. 2단계에서 위계 제약을 **인접 위계까지 허용**으로 완화한 **재검색 1회**. 재검색을 했는지 여부를 trace에 남긴다(`hierarchy_relaxed_retry`).
2. 확신도가 `[T_new, T_merge)`면 `ask_user(kind="identity")`
3. 확인되면 `update_person`으로 `person_aliases`에 새 호칭 누적 + `display_name`을 **사용자가 확인한 가장 최근 호칭**으로 갱신. 이전 호칭은 별칭으로 남아 카드 상단에 "이전: 김팀장"으로 표시된다.

## person_aliases 누적

확인된 호칭은 항상 `person_aliases(person_id, alias, source, embedding, confirmed_at)`에 쌓고 **별칭 임베딩도 함께 저장**한다. 이 누적이 시간이 갈수록 1단계 후보 검색 정확도를 높인다.

## 품질 체크 (구현/검토 시)

- [ ] 4단계가 모두 존재하는가 (하나라도 생략 금지)
- [ ] `T_merge` 미만에서 자동 병합이 절대 일어나지 않는가
- [ ] `T_new` 미만에서 확인 없이 신규 인물을 만들지 않는가
- [ ] 규칙 필터가 위계·소속 제약을 적용하는가
- [ ] 확신도가 3신호 결합인가 (로그 확률을 쓰지 않는가)
- [ ] 보정표(`reports/calibration.json`)가 있는가
- [ ] 승진 케이스 회귀 테스트가 있는가 (위계 완화 재검색 포함)
- [ ] 판정 근거(후보 목록·`confidence_breakdown`·결정)가 agent_traces에 남는가
