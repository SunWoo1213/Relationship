# L-005 · 메인 세션은 원문·실제 출력을 직접 보고 말하고, 결정·문제는 그때 journal 에 남긴다

날짜: 2026-09-24 | 어디서(P / FIX / CR): P5-loop 계획 단계(2026-09-23~24) · FIX-002 · FIX-003 | Refs: L-005 P5-loop FIX-002 FIX-003 원칙8

## 무슨 일이 있었나
메인 세션(조율 담당)이 P5-loop 계획을 조율하면서 한 실수 셋과 기록 누락 하나. 앞의 셋은 HANDOFF "주의"란에만 적혀 있어서, HANDOFF 를 덮어쓰면 사라질 처지였다(2026-09-24 사용자 점검 요청으로 발견).

1. **기획서 원문을 열지 않고 설명했다.** 결정 L(툴 선택을 LLM 이 하는가)을 설명하면서 원칙1·4 와 CLAUDE.md 만 보고, `docs/proposal.md` 72행(LLM 역할)은 확인하지 않았다. 권위 문서들이 이 점에 대해 말이 없었는데도 원문을 직접 열지 않았고, 결정 L 은 결국 (i)→(iii) 으로 바뀌었다.
2. **증거 파일명을 손으로 적어 틀렸다.** `FIX-002.md` 에 evidence 파일명을 `…1518…` 로 적었는데 실제는 `…1526…` 이었다(정정 완료).
3. **훅 판정을 종료 코드로 읽었다.** `stage-gate.sh` 는 거부할 때도 exit 0 이고 판정은 출력 JSON(`"deny"`)에 있다. 종료 코드만 보고 "가드가 안 막는다"고 잘못 보고했다가 정정했다.
4. **오늘 결정·문제가 journal 에 한 줄도 없었다.** M-3 결정, verify-plan 3회, verifier 로드 실패(FIX-003)를 HANDOFF 에만 적었다. journal 은 append-only 이력이고 HANDOFF 는 덮어쓰는 문서다.

## 왜 그랬나
- 1·2·3 은 같은 뿌리다 — **확인했다고 믿은 것과 실제로 본 것을 구분하지 않았다.** 요약본·기억·관례(exit code 의미)가 원문·실제 출력을 대신했다. verification.md 의 "검증은 가시적 증거로만" 은 서브에이전트 산출물에는 적용했지만 메인 세션 자신의 설명·기록에는 느슨했다.
- 4 는 HANDOFF 갱신을 Stop 훅이 강제하는 데 비해 journal 에는 강제 장치가 없어서(COMMIT 줄만 훅이 자동 기록) 비용이 적은 쪽으로 기록이 쏠렸다.

## 다음부터
- **원칙이나 결정을 설명할 때**: 권위 문서(CLAUDE.md·카드)에 답이 없으면 `docs/proposal.md` 해당 절을 직접 열어 인용한다. 인용 없이 "기획서 취지상" 이라고 말하지 않는다.
- **파일명·해시·행 번호는 손으로 옮겨 적지 않는다.** `ls`·`git log`·`grep -n` 출력을 그대로 붙인다.
- **훅 판정은 출력으로 읽는다.** PreToolUse 훅은 exit 0 + `permissionDecision` JSON 으로 거부한다. 판정 확인은 `| grep '"deny"'`(test-guards.sh 의 `expect_deny` 와 같은 방식).
- **사용자 결정·검증 실행·실패(FIX/소견 발생)마다 그 자리에서 journal 에 한 줄**(DECISION·VERIFY·FIX·NOTE). HANDOFF 는 "지금 어디"만, 이력은 journal 이다. 규칙 변경은 없다 — 이미 devlog SKILL 과 journal 머리말에 있는 규칙을 메인 세션이 지키지 않은 것이다. 강제 장치(훅)가 필요한지는 `lessons/CANDIDATES.md` 에 올린다.
