# S3.4 · ask_user 프로토콜

원문: `docs/resolution-plan.md` §3.4 · 관련: D1 D2 · 적용: P2-tools, P5-loop, P8-frontend

```
턴 N   발화 → 루프 → ask_user → pending_questions 저장 → 응답에 question_id → 턴 종료
턴 N+1 칩 선택 → POST /answers/{question_id} → 저장된 context로 루프 재개 → 후속 툴
```

- 답 없이 다음 발화가 오면 대기 질문 유지, 새 발화 우선.
- 미답변 24시간 후 만료(`answered_at` null 유지, status=expired).
- 프론트 확인 칩 = 미답변 pending_questions.
- `context`에는 재개에 필요한 것만(발화, 후보 id, 확신도 분해). 비밀·전체 대화 이력 저장 금지.
- (CR-006 · D18, 2026-11-15) 질문 행은 만든 계정의 `user_id` 를 갖는다. `POST /answers/{question_id}` 는 로그인 사용자와 `user_id` 가 같을 때만 받고, 아니면 404(행·`answer` 변화 0). 미답변 질문 조회(`GET /questions/pending`)도 로그인 사용자의 채팅방(`session_id = chat:<user_id>`) 기준이다. 프로토콜(저장 → 턴 종료 → 칩 → 재개)은 그대로.
- (CR-004 · D16, 2026-10-28) 조회 발화의 `identity` 되묻기는 같은 프로토콜을 쓰고, 재개 재료(`PendingResume`)에 `intent`("record"/"query") 1필드가 더해져 답 뒤 재개가 조회로 이어진다. `new_person` 구간의 조회 발화는 되묻지 않는다(질문 행 생성 0).
- (CR-009 · D20, 2026-11-22) **`kind="sensitive"` 두 갈래.** 프로토콜(저장 → 턴 종료 → 칩 → 재개)은 그대로.
  - ① **사전 동의**(phase `pre`): LLM 전 서버 규칙 검사에 동의 범주가 걸리면 라우트가 `ask_user` 툴을 부르지 않고 질문 행을 쓴다. context = 가린 원문(`utterance`)·`categories`·`rule_ids`·대화 기록 줄 id·긍정 칩. 긍정 재개 = 그 문장으로 **턴을 처음부터**(추출 LLM 포함 — 동의 전에는 인식을 하지 않았으므로). 조회형 문장도 같은 칩(중립 문구).
  - ② **사후 확인**(phase `post`, 기록·조회 모두): 추출 LLM 이 민감 범주를 표시하면 게이트 직후·의도 분기 앞에서 루프가 `ask_user` 로 묻는다(ER 판정·임베딩·조회 답 LLM 전). 긍정 재개 — 기록은 보류 제안 실행 경로(인식 LLM 재호출 없음), **조회는 언급 해석 단계부터 다시 돈다**(인식 LLM 재호출 없음 — 사후 질문은 ER 앞에서 멈췄으므로 후보가 없다. 기존 identity 답 전용 조회 재개 경로를 쓰지 않는다). 그래서 조회의 context 에는 게이트 통과 보류 제안이 아니라 제안의 툴 호출(또는 언급 목록)을 싣는다. 함수·context 정확한 모양은 P9d 01-plan U6.
  - 동의 문맥은 그 턴의 모든 후속 질문 context 에 예약 키 `consent = {question_id, categories}` 로 실리고 재개 바이트 절단에서 잘리지 않는다(D20 R-9). 긍정 답 규약은 기존 형식 — `context[AFFIRMATIVE_KEY]` 는 비어 있지 않은 문자열 리스트(R-11).
  - 거절·만료: context 는 남기는 키(`phase`·`intent`·`categories`·`rule_ids`·`chat_message_id`·`turn_trace_range`·`AFFIRMATIVE_KEY`·`redacted`) 밖을 전부 지우고, 대화 기록 줄은 "(기억하지 않은 민감한 내용)", 사후 경로는 그 턴 trace 의 `input`·`output` 도 지운다(D20 R-2·R-3). 만료 정리는 1분 주기 작업의 독립 단계. 위 13행의 "`context` 에는 재개에 필요한 것만" 은 그대로다.
  - 동의 문맥 없이 재개되는 질문(배포 전 질문)은 저장된 발화를 다시 검사해 걸리면 재개하지 않는다(409 `expired` 와 같은 응답, D20 R-10).
