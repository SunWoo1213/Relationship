# S3.2 · 툴 시그니처 v2

원문: `docs/resolution-plan.md` §3.2 · 관련: D1 D2 D6 R10 · 적용: P2-tools

| 툴 | 시그니처 | 비고 |
|----|----------|------|
| `search_person` | `(query: str, hints?: {hierarchy?, relation_tag?}) → Candidate[]` | 규칙 필터 힌트 |
| `create_person` | `(display_name, aliases: str[], relation_tag, hierarchy) → Person` | D1: answered new_person 질문 뒤에만 |
| `update_person` | `(person_id, facts?: {key,value}[], new_alias?: str, display_name?: str) → Person` | 승진: 별칭 누적 + 표시 이름 갱신(D6) |
| `add_event` | `(person_id, type, content, occurred_at, raw_utterance) → Event` | 런타임이 raw_utterance 자동 주입 |
| `add_schedule` | `(person_id, title, scheduled_at) → Schedule` | |
| `get_briefing` | `(person_id, schedule_id?) → Briefing` | `briefed_at` 기록 |
| `ask_user` | `(kind, question, options, context) → PendingQuestion` | D2 비동기. 독립 툴 유지 |

`Candidate = {person, similarity, aliases_matched, rule_flags}` — 3단계 LLM 판정 입력.
모든 툴 호출은 `agent_traces`에 input/output/tokens 기록(원칙9).

**보충(CR-009 · D20, 2026-11-22)** — 툴 7종의 **개수·시그니처는 그대로**(`tools_check` 7/7).
- `ask_user.kind` 값 집합 4종: `identity`·`new_person`·`schedule`·`sensitive`. 사전 동의 질문은 툴을 부르지 않고 저장소에 직접 쓴다(D2 보충) — 툴로 부르는 `sensitive` 는 사후 확인뿐.
- `get_briefing` 은 민감 표시된 사실·최근 사건·다가오는 일정을 **돌려주지 않는다**(반환 모양 무변경, 돌려주는 항목만 준다. 최근 사건 상한은 거른 뒤 채운다. 민감 대상 일정이면 `ScheduleNotFound`). 거른 결과만 `@traced` output 에 남는다. 호출자는 브리핑 입력 하나.
- 이름 규칙(D20 R-7): 민감 낱말이 든 표현은 별칭·표시 이름으로 저장되지 않는다. 판정은 **툴 밖·`app/er/` 밖, 에이전트 루프(`app/agent/loop.py`) 안**에서 한다 — 기록 의도 턴의 게이트 뒤·해석(`resolve_mentions`) 앞에서 걸린 언급의 제안을 게이트 판정의 거부 쪽(사유 `name_rule`)으로 옮겨 언급을 ER(`resolve()`)에 넘기기 전에 거르므로, 자동 연결 때 언급을 별칭으로 더하는 `update_person(new_alias=…)`(ER 적용)과 identity·new_person 답 재개의 별칭·표시 이름 저장에 그 언급이 닿지 않는다. 재개 쪽은 방어 판정을 한 번 더 둔다. 루프가 LLM 제안을 실행하는 자리에서는 `update_person` 의 `new_alias` 만 거른다(그 자리는 `display_name` 을 넘기지 않고, `display_name` 제안은 게이트가 먼저 거부한다). 거른 언급의 제안은 버리고 다른 언급의 되묻기 context 에도 싣지 않는다. 정확한 함수·줄 자리는 P9d 01-plan 에서 닫는다. **예외(사용자 결정 22)**: 그 사용자의 이미 저장된 별칭과 **글자까지 같은** 언급은 동의 문맥이 있는 턴에서 통과한다(메인 세션 결정 — 공백·대소문자만 다른 변형은 거부. 별칭 저장은 같은 글자 행이 있으면 새 행·임베딩을 만들지 않으므로 새로 저장되는 이름이 없다). 별칭 주인이 아닌 인물로 해석될 때는 P9d 01-plan D-4.
- `create_person`·`update_person`·`add_event`·`add_schedule` 의 인자·반환 타입은 늘지 않는다 — 동의 문맥은 `ToolContext.consent` 로 싣고, **툴이 그것을 읽어 기록하는 같은 INSERT/upsert 문에서** `sensitive_category`(사건은 `consent_question_id` 도)를 채운다(사실은 `COALESCE(기존, 이번)` — S3.5).
