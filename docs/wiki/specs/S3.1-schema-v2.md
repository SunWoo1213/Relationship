# S3.1 · 스키마 v2

원문: `docs/resolution-plan.md` §3.1 · 위: D2 D5 (R8 R12) · 아래: P1-schema · 이웃: S3.2(툴이 이 스키마를 쓴다)

```sql
persons(id, user_id, display_name, relation_tag, hierarchy, created_at, updated_at)
person_aliases(id, person_id, alias, source, embedding vector(1536), confirmed_at)  -- N=1536: D4 확정(text-embedding-3-small, reports/embed_pilot.md)
person_facts(id, person_id, key, value, confidence, updated_at)
fact_sources(fact_id, event_id)                          -- 시맨틱 사실 → 근거 원문
events(id, person_id, type, content, raw_utterance, occurred_at, created_at)
schedules(id, person_id, title, scheduled_at, briefed_at)
pending_questions(id, session_id, kind, question, options, context, answer, created_at, answered_at)
push_subscriptions(id, user_id, endpoint, keys, created_at)
agent_traces(id, session_id, step, tool_name, input, output, tokens_in, tokens_out, created_at)
```

- `person_embeddings` 없음 (D5).
- `events.type` CHECK 제약: `conflict / praise / meal / meeting / personal_share / favor / other`.
- `relation_tag` ∈ {가족, 연인, 친구, 직장, 지인}, `hierarchy` ∈ {상, 동, 하}.
- `person_aliases.source` ∈ {user_said, confirmed, system} (P2-tools 결정 5, 앱 검증·DB CHECK 없음).
- `pending_questions.kind` ∈ {identity, new_person, schedule}.
- `agent_traces.output`(ER 단계): `candidates[]`, `confidence_breakdown{}`, `decision`.
- 인물–인물 관계 테이블 없음 (D8, 원칙7).
- 인물 단위 완전 삭제가 가능해야 함(기획서 9장 개인정보) → FK ON DELETE CASCADE.
