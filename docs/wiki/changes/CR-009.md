### 4.4 D20 규칙 (개정 1 에서 새로 고정한 것 — D20 카드로 옮긴다)

- **R-1 원문 보관 자리(사용자 결정 8)**: 사전 동의 대기 중 원문(차단 유형은 가린 것)은 `pending_questions.context.utterance` 와 그 사용자 줄 `chat_messages` 한 줄에만 있다. 사전 경로는 `ask_user` 툴을 부르지 않으므로 trace 에 원문이 들어가지 않는다(`ask_user` 는 `@traced` — `app/tools/questions.py:183`, `app/tools/context.py:190~193` 이 인자 전부를 trace 입력에 넣는다).
- **R-2 거절·만료 때 질문·대화 기록에서 지우는 것(사전·사후 공통, 개정 2 — RM2)**: `kind='sensitive'` 질문의 `pending_questions.context` 는 **남기는 키 — `phase`·`intent`·`categories`·`rule_ids`·`chat_message_id`·`turn_trace_range`·`AFFIRMATIVE_KEY`(칩 문자열)·`redacted`(true) — 밖의 키를 전부 지운다.** 그러므로 `utterance`·`pending_calls`(제안 인자 = 사건 내용·사실 값·일정 제목)·`held_drafts`·`mention`·`resume`·`hints`·`candidate_ids` 등 지금 있거나 앞으로 더해질 키가 모두 사라진다(지우는 쪽을 열거하지 않는다). 대화 기록 줄(`chat_message_id`) `content` → "(기억하지 않은 민감한 내용)". 남는 것: 질문 행·`question`·`options`·`answer`·`answered_at`·위 남기는 키·`guard_check` trace.
- **R-3 거절·만료 때 trace 에서 지우는 것(사후, 개정 2 — RM2)**: 같은 `session_id` 이고 id 가 `turn_trace_range` 구간 `(직전, 직후]` 인 **모든** trace 행(그 턴의 `loop_extract`·`loop_gate`·`ask_user`·`loop_turn` 등 — U6 의 모으는 방법)의 `input`·`output` 을 `{"redacted":"sensitive_declined","categories":[...],"rule_ids":[...]}` 로 바꾼다. 행 자체·step·tool_name·토큰·시각은 남긴다. 거절 분기는 `resume_turn` 앞에서 끝나므로 재개 진입 trace 는 생기지 않는다(U5c). 사전 경로는 구간이 없다(trace 에 원문이 들어가지 않으므로 — R-1). 이것이 trace 를 덮어쓰는 **유일한** 자리(`app/guard/consent.py::redact_declined`)다. 원칙9 와의 관계는 2.4 원칙9 행.
- **R-4 남는 흔적**: 거절 뒤에도 범주·규칙 id 가 남는다 — 그 자체가 "이 사람에 대해 어떤 범주의 말을 했다" 는 흔적이다(R3). 규칙 id 는 낱말을 드러내지 않는 번호다. 이것은 받아들인 위험이다(7절 W15).
- **R-5 사실 표시 단일 규칙(M4)**: 사실의 민감 여부는 **`person_facts.sensitive_category` 컬럼 하나**로 정하고, 모든 쓰기(`update_person` upsert `persons.py:613~631`, `direct_facts.py`, 승격 `_upsert_fact` `promote.py:147`)는 `sensitive_category = COALESCE(기존값, 이번 쓰기의 범주)` 로만 바꾼다 — **올라가기만 하고 내려가지 않는다.** 같은 키를 일반 턴이 덮어도 민감으로 남는다(옛 민감 사건 링크가 `fact_sources` 에 남기 때문 — 링크를 끊지 않는다). 승격의 "값 같음" 분기도 같은 식. `fact_sources` 로 파생하지 않는다. 결과로 "민감 사건에 링크된 사실은 항상 민감" 이 성립한다. 근거 원문 조회는 사실 표시와 별개로 **사건 표시로도** 거른다(브리핑 `_fact_sources`). 과잉 표시는 안전한 쪽 오류(원칙1 비대칭).
