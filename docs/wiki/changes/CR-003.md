## 1. 무엇이 바뀌는가

기획서 본문(`docs/proposal.md`)은 인물 화면의 **배치**를 정하지 않는다 — 부록 A ②(318행~)는 카드 한 장의 내용(이름·태그·별칭·마지막 접촉·알고 있는 것·반복 패턴·타임라인)만 보여 준다. 배치는 P8-frontend 01-plan 의 **결정 N**(모든 폭 왼쪽 사이드바 + 사이드바 아래쪽에 인물 목록 전원)과 **U6**("`#/persons` 인물 목록(이름·태그·위계·마지막 접촉, **필터 컨트롤 없음** — 같은 목록 컴포넌트를 사이드바 아래쪽에도 그린다, **새 API·새 라우트 없음**)") 이 정했다. 그러므로 **기획서 본문은 그대로**, 바뀌는 것은 P8 계획의 결정 N·U6 와, 그것을 고정한 새 결정 카드다.

| 어디 | 이전 | 새(안) |
|------|------|--------|
| `#/persons` 인물 화면 | 세로 목록(이름·태그·위계·마지막 접촉). 항목을 누르면 같은 화면 아래에 카드가 펼쳐진다 | **카드 그리드** — 타일마다 이름·관계 태그·위계·마지막 접촉(·별칭 1~2개). 타일을 누르면 `#/persons/:id` 상세(지금 카드 그대로). 데스크톱 2~3열, 모바일 1열 |
| 인물 화면 검색 | 없음(U6 "필터 컨트롤 없음") | **검색창 1개** — 이름·별칭 부분 일치. 입력하면 그리드가 바로 줄어든다. **관계 태그 필터는 넣지 않는다**(아래 "범위") |
| 사이드바 인물 목록 | 전원(`PersonList` 같은 컴포넌트) | **최근 5명**(기준은 §3 결정 ①) + "전체 보기 →"(`#/persons`) 링크 |
| 정렬·폭 규칙(**PC 웹 기준** — 사용자 2026-10-16 추가) | U10 수정 1회(미커밋): 인물 화면 전체 왼쪽 정렬 `max-w-4xl`(896px 고정) | **목록/그리드**: 본문 폭 전체(왼쪽부터) · **상세(`#/persons/:id`)**: 가운데, 폭은 고정 px 가 아니라 **창 크기에 비례**(예: 본문 폭의 75%, 모바일 100%) — "인물 상세보기를 했을 때는 왼쪽으로 치우치지 않으면 좋겠어", "창의 크기에 따라 비율을 맞춰야 해" |

- **범위(기획서 2장 표)**: 포함 칸 "인물 카드 (사실 · 타임라인 · 마지막 접촉)" 안의 변경이다. **제외 칸 "관계 태그 필터링"은 움직이지 않는다** — 검색은 이름·별칭 문자열만 받고 태그로 거르는 컨트롤을 두지 않는다. 태그 필터까지 원하면 2장 표의 칸이 움직이므로 **별도 CR** 이다.
- 불변 원칙 5(화면 3개 고정)는 지킨다 — 화면은 여전히 채팅/인물/브리핑 셋이고, 상세는 이미 있는 `#/persons/:id` 경로다. 원칙 7(제외 범위)은 위 "범위" 대로.
- 서버 문자열을 프론트가 바꾸지 않는다(결정 L 경계·원칙7) — 타일 문구는 서버 값 그대로, 검색은 그 값의 부분 일치.
