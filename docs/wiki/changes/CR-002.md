# CR-002 · 반복 패턴 기간·횟수를 설정값으로, 기본값 1년(365일)·3회

상태: 이행완료(문서, 2026-09-28 — D14 신설·D9 대체·S3.5·CLAUDE.md 원칙6·resolution-plan·proposal 상단·backlog P6·review-index R11·INDEX·backend-agent·P6-memory 01-plan; 코드 이행은 P6-memory U1·U2) | 제기: 2026-09-28, 사용자 (P6-memory 01-plan 결정 확정 중 "90일은 너무 짧다, 1년으로" → 선택지 중 "기간·횟수를 설정값으로" 선택)

## 1. 무엇이 바뀌는가

기획서 본문(`docs/proposal.md`)에는 기간 숫자가 없다(241·353행 "최근 3회" 뿐) — **본문은 그대로**, 상단 "원본 이후 확정된 사항"에 한 줄만 는다. 바뀌는 문장:

| 어디 | 이전 문장 | 새 문장(안) |
|------|----------|------------|
| D9 결정 · `CLAUDE.md` 원칙6 · S3.5 · resolution-plan §3.5 · `.claude/agents/backend-agent.md` | 같은 인물의 같은 `events.type` 이 **90일 내 3회 이상** → `pattern:{type}` | 같은 인물의 같은 `events.type` 이 **설정된 기간(`PATTERN_WINDOW_DAYS`, 기본 365일 = 1년) 내 설정된 횟수(`PATTERN_MIN_COUNT`, 기본 3회) 이상** → `pattern:{type}` |
| `docs/backlog.md` P6 첫 항목 수용기준 | "승격 후 사실→원문 링크 존재, 90일 3회 규칙으로 `pattern:{type}` 사실 생성" | "승격 후 사실→원문 링크 존재, 설정된 기간·횟수 규칙(기본 365일 3회)으로 `pattern:{type}` 사실 생성" |

- **바뀌지 않는 것**: 규칙 기반(LLM 은 판정하지 않고 문장화만, 원칙6) · `value="{n}회 (날짜 목록)"` · `confidence=1.0` · 근거 이벤트를 `fact_sources` 로 연결 · 원문 삭제 금지. D9 "코드에서 지켜야 할 것" 의 "90일·3회는 설정값" 은 이미 설정값을 요구했다 — 이번 CR 은 **기본값을 90→365 로 바꾸고, 설정 수단(환경변수)을 명시**한다.
- 1년 = **365일 고정**(윤년 무관, 재현성 — 원칙8). 창 = `[now − PATTERN_WINDOW_DAYS일, now]`, `occurred_at` 기준(P6-memory 결정 C-2).
- 환경변수 `PATTERN_WINDOW_DAYS`·`PATTERN_MIN_COUNT`(양의 정수, 잘못된 값이면 오류; 비우면 기본값). `.env.example` 에 기본값 줄 추가.
- 범위(기획서 2장 표)는 움직이지 않는다. 불변 원칙 1~5·7~9 유지.

**트레이드오프(사용자에게 설명함)**: 창이 길수록 패턴이 많이 생긴다 — 명절 식사 같은 일상도 1년 3회면 패턴이 된다. 그래서 횟수도 설정값으로 두어, 파일럿·데모에서 너무 많으면 코드 수정 없이 올릴 수 있게 한다. 90일로 되돌리는 것도 설정 한 줄이다.
