# P9b-auth U8 · 시연 계정에 넣을 대화 (메인 세션 작성, 2026-11-16)

> 목적: 시연 (나) "이미 데이터가 들어가 있으면 어떻게 해 주는지" 를 보이기 위해, 배포본의 **시연 계정**에 제품 파이프라인 그대로(채팅) 데이터를 쌓는다. DB 에 직접 넣지 않는다(결정 Q).
> 이 목록은 제안이다 — 인물·내용은 사용자가 바꿔도 된다. 평가 데이터셋·라벨과 무관하다(원칙8).
> 확인 칩이 뜨면 **사용자가 직접 판단해 누른다**. 아래 "기대" 는 흐름 설명이지 정답 강요가 아니다(원칙1 — 자동 병합을 유도하지 않는다).
> 한 줄씩 보내고 답을 본 뒤 다음 줄을 보낸다. 발화 하나는 2000자까지.

## 언제 넣나
- 배포 반영(13 문서 G-3~G-6)과 시연 계정 가입(G-7) 뒤, **11-17(화) 저녁**에 1~12번을 넣는다.
- 13번(일정)은 **시연 시각 기준 24시간 안**이어야 브리핑이 만들어진다. 11-17 저녁에 넣는다면 "내일(11-18) 시연이 끝난 뒤 시각" 으로 잡는다. 넣고 1~2분 뒤 브리핑 화면에 브리핑이 생긴다(한 일정에 브리핑은 한 번만 만들어진다).

## 넣은 뒤 볼 것 (리허설 — 13 문서 G-9)
1. 인물 화면: 4명 카드. 김민수 카드에 사실·타임라인·패턴, 원문 펼침.
2. 브리핑 화면: 13번 일정의 브리핑 1건.
3. 로그아웃 → 다시 로그인: 위 대화가 채팅 화면에 이어서 보인다(최근 50줄).
4. 로그아웃 → **새 계정 가입**: 인물 0명, 채팅 기록 없음. 여기서 "오늘 김민수 팀장님 만났어" 를 보내면 시연 계정의 김민수와 무관하게 **새 인물 확인 칩**이 뜬다(계정 간 기억이 섞이지 않음).
5. 다시 시연 계정으로 로그인: 1~3이 그대로.

## 시연 계획 (2026-11-17 밤 개정 — 사용자 "시연에 맞게 계획을 세우고 구현을 진행해주세요")

시연 전략은 사용자가 정한 두 갈래다(CR-006 원문): **새 계정을 만드는 모습**을 보이고, **이미 데이터가 들어 있으면 어떻게 해 주는지**를 보인다. 성능을 보이는 쪽은 미리 채운 계정이다. 그래서 준비의 중심은 "시연 계정의 인물 카드가 사실·타임라인·반복 패턴·브리핑을 실제로 보여 주는 상태"를 만드는 것이다.

### 지금 막힌 것
11-16 배포본에 위 13발화를 넣었을 때 김민수 카드는 사실 0건·반복 패턴 없음이었다(`evidence/20261116-2230-u8-deployed-demo-script-run.txt`). 원인과 수정은 `fixes/FIX-037.md`(인식 프롬프트·조회 답 프롬프트). 이 수정이 배포돼야 시연 계정이 제 모습을 갖춘다.

### 준비 순서
1. **FIX-037 구현 → 수정 전후 측정 → verifier 리뷰 → 커밋**(에이전트). 새 배포 해시를 13 문서에 적는다.
2. **재배포**(사용자, SSH — 13 문서 H 절과 같은 명령에 새 해시).
3. **시연 계정을 새로 만든다**(사용자 가입). 지금의 `test` 계정에는 잘못 분류된 사건(지적이 `praise` 등)이 남아 있어 그대로 쓰지 않는다.
4. **1~12번 발화를 넣는다.** 발화 하나를 보낼 때마다 답을 본다. "새로 기억한 것이 없어요"·"기록하지 못했어요"가 나오면 같은 내용을 한 번 더 보낸다 — 같은 발화도 호출마다 결과가 달라지기 때문이다. DB 에 직접 넣지 않는다(결정 Q).
5. **카드 상태를 확인한다**: 김민수 카드에 사실 1건 이상, 타임라인 4건 이상, 반복 패턴(갈등 3회) 표시. 패턴이 안 생기면 갈등 발화를 문장을 바꿔 하나 더 넣는다(예: "오늘도 김민수 팀장님이랑 회의에서 의견이 크게 갈려서 다퉜어").
6. **13번(일정)은 시연 시각이 24시간 안에 들어오도록** 넣는다. 한 일정에 브리핑은 한 번만 만들어지므로 시각을 틀리게 넣었으면 일정 발화를 새로 보낸다.
7. **리허설**(아래 "심사 자리 흐름"을 처음부터 끝까지 한 번).

### 심사 자리 흐름 (약 3분)
1. **새 계정 가입**: 아이디·닉네임 "중복 확인" → 가입 → 인물 0명, 빈 채팅. "오늘 ○○○ 과장님이랑 점심 먹었어" 한 줄 → 새 인물 확인 칩 → 관계 선택 → 인물 카드 1장. (이름이 있는 새 인물 + 사건 한 건 — 11-16 실행에서 가장 안정적으로 기록된 꼴.)
2. **로그아웃 → 시연 계정 로그인**: 지난 대화가 그대로 보인다. 인물 화면에서 김민수 카드 — 사실, 타임라인(원문 펼침), 반복 패턴.
3. **브리핑 화면**: 13번 일정의 브리핑(최근 사건 + 한 줄 제안).
4. **(FIX-037 배포·확인된 경우에만)** 채팅에 "김민수 팀장님 최근에 무슨 일 있었어?" → 기록된 사건을 날짜와 함께 답한다. 이 문형은 수정 전에도 정상이었다. "요즘 어때?"는 리허설에서 3번 연속 정상일 때만 쓴다.
5. **계정 격리 한마디**: 1번에서 만든 새 계정에는 김민수가 없었다 — 계정마다 기억이 따로다.

### 어긋났을 때
- 재배포가 시연 전에 안 되면: 4번을 빼고, 2번은 타임라인·브리핑 중심으로 보인다(사실·패턴은 "대화가 쌓이면 채워진다"고 말한다). 발표 자료 4장이 지금 이 상태에 맞춰져 있다.
- 즉석 입력이 기록되지 않으면: 같은 말을 다시 보내지 말고 2번으로 넘어간다. 리허설 때 찍어 둔 화면 캡처를 예비로 둔다.
- 재배포·시연 계정이 계획대로 되면 발표 자료 4장의 인물 카드 예시를 실제 카드 내용(사실·반복 패턴)으로 되돌린다.

2. **로그아웃 → `test` 로그인(쌓인 상태, 90초)**: 왼쪽에 인물이 보인다 → **김민수** 카드. 순서대로 짚는다: 알고 있는 것(녹차, 아침 보고) → "근거 보기" 한 번 → **반복 패턴 "갈등 3회"** → 다가오는 일정. 말할 것: "같은 유형의 일이 세 번 쌓이면 규칙으로 패턴을 만듭니다. LLM 이 지어낸 게 아니라 근거 사건이 연결돼 있습니다."
3. **브리핑(30초)**: 브리핑 화면 → 분기 리뷰 회의 브리핑(최근 사건 + 한 줄 제안). 말할 것: "만나기 전에 기록에서 나온 것만 요약합니다. 상담이나 조언은 하지 않습니다."
4. **질문(30초)**: 채팅에 "김민수 팀장님 요즘 어때?" → 날짜와 함께 최근 일을 답한다. 리허설에서 답이 이상하면 "김민수 팀장님 최근에 무슨 일 있었어?" 로 바꾼다.
5. **호칭만으로 찾기(20초, 선택)**: "팀장님이 오늘 회의 자료를 칭찬해 주셨어" → 김민수 카드에 붙는지(또는 확인을 묻는지) 보인다. 리허설에서 먼저 해 보고 결과가 깔끔할 때만 쓴다.
6. **MCP(40초, 연결이 확인된 경우에만)**: 터미널의 Claude Code 에서 "relmemo 에서 김민수 팀장님에 대해 알려 줘" → 인물 카드 내용이 답으로 온다. 말할 것: "쌓인 기억을 다른 AI 도구에서도 읽기 전용으로 꺼내 씁니다." 연결이 안 됐으면 이 단계와 발표 자료의 MCP 장을 뺀다.
7. **계정 격리 한마디**: 1번의 새 계정에는 김민수가 없었다.

### 아침에 할 일 (사용자)

- `relmemo.com` 에 `test` 로 로그인돼 있는지, 브리핑 화면에 11-18 일정 브리핑이 있는지 확인.
- MCP: 웹에서 연결 토큰을 만들고 Claude Code 에 붙이는 명령을 직접 실행(토큰 값은 채팅·문서에 적지 않는다). 절차는 MCP 배포가 끝나면 이 문서에 덧붙인다.
- 위 흐름을 처음부터 끝까지 한 번 리허설. 1번에서 만든 리허설용 계정은 실제 시연 때 다른 아이디로 다시 만든다.
- OpenAI 사용량 확인.
