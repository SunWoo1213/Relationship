# U7 로컬 브라우저 점검 (메인 세션, 실제 Chrome — 2026-11-16 04:00)

성격: 사람 눈 점검을 메인 세션이 브라우저 자동화로 대신한 관찰 기록이다(명령 출력이 아니다). 화면 캡처는 저장하지 않았다.
구성: 프론트 `npm --prefix web run dev`(http://localhost:5173, Vite 프록시 `xfwd`) → 백엔드 http://localhost:8000.
  - 8000 포트에는 사용자가 이미 띄워 둔 백엔드(`--reload`)가 돌고 있어 그것을 그대로 썼다(`/health` → alembic_revision 0003, 쿠키 없이 `/auth/me` 401 확인).
    메인이 따로 띄우려던 백엔드는 "address already in use" 로 뜨지 않았다. 그 서버의 `AUTH_COOKIE_SECURE` 값은 확인하지 않았다.
DB: 개발 DB(0003). 점검용 계정 1개(`u7browser01`)와 그 대화 2행·대기 질문 1건이 남는다. 비밀번호는 기록하지 않는다.

| # | 한 일 | 본 것 |
|---|---|---|
| 1 | http://localhost:5173/ 열기 | 로그인 화면(아이디·비밀번호·"로그인"·"계정 만들기") — 앱 틀은 보이지 않음 |
| 2 | "계정 만들기" | 가입 화면(아이디·비밀번호·비밀번호 확인·규칙 안내 한 줄·"가입하기") |
| 3 | 아이디·비밀번호 입력 후 Enter | 앱 틀로 전환, 주소 `#/chat`, 사이드바 아래 "u7browser01 · 로그아웃", 채팅 "메시지를 입력해 대화를 시작하세요.", 사이드바 "아직 기록된 인물이 없어요." |
| 4 | "오늘 박지훈 선배랑 점심 먹었어" 전송 | `POST /api/chat` 200. 답 "이번 발화에서는 새로 기억한 것이 없어요. "박지훈"을(를) 새 인물로 기억해둘까요?" + 확인 칩 6개(가족/연인/친구/직장/지인으로 기억할게요, 아니요) |
| 5 | 새로고침 | 로그인 유지(`GET /api/auth/me` 200), `GET /api/chat/history?limit=50` 200·`/api/questions/pending` 200·`/api/persons` 200. 보낸 말과 답이 그대로 보이고 칩이 그 답 줄에 붙어 있음 |
| 6 | "로그아웃" | 로그인 화면으로 돌아감 |
| 7 | 같은 계정으로 로그인 | 4번의 대화와 칩이 그대로 보임 |

판정: 실제 브라우저에서 가입·로그인 유지·대화 기록 복원·로그아웃·재로그인이 동작하고, 같은 출처 POST(가입·로그인·채팅·로그아웃)가 Origin 검사에 막히지 않았다(개발 프록시 경유).
확인하지 못한 것: 운영 주소(HTTPS, Caddy 뒤)의 실제 브라우저 동작 — 사용자 몫(13 문서 G-7). 두 계정을 오가는 화면 전환·푸시 알림은 이 점검에서 하지 않았다.
