- **시간 주입 방식(위임 프롬프트가 "기존 방식을 따르고 03-log 에" 라고 지시한 것)**: `/chat`·`/answers/{id}`(P5-loop)는 `ToolContext.now` 를 주입할 방법이 없다 -- 두 엔드포인트 모두 "지금"이 결과를 가르지 않기 때문이다(이벤트는 요청 본문의 `occurred_at` 을 그대로 쓴다). 반면 이 엔드포인트는 `select_due_schedules()`(U2)가 `scheduled_at` 과 "지금"의 차이로 대상을 고르므로 시간 고정이 꼭 필요하다. 그래서 비-HTTP 테스트 전부가 쓰는 "`ToolContext.now` 에 고정 함수를 주입한다"는 관례를, `get_proposer`/`get_judge`/`get_embedder` 와 같은 모양의 새 FastAPI 의존성 `get_now()` 로 HTTP 경계에 옮겼다 -- 새 메커니즘이 아니라 기존 두 관례(ctx.now 주입 + 의존성 오버라이드)를 합친 것이다.
- **부분 롤백 장치를 두지 않은 이유**: `/chat`/`/answers/{id}` 가 `run_turn()`/`resume_turn()` 호출 전체를 `session.begin_nested()` 로 감싸는 것은 "언급 여러 개 중 하나가 실패하면 그 턴 전체를 저장 0 으로 되돌린다"는 루프 고유의 요구(결정 G) 때문이다. `run_briefings()`(U5)는 이미 일정 하나하나를 자신의 `begin_nested()` 로 감싸 실패를 격리하므로(판정 22행), 이 라우트가 호출 전체를 또 한 번 감싸면 오히려 "성공한 일정도 실패한 일정과 함께 되돌려진다"는 **잘못된** 동작이 된다. 그래서 이 엔드포인트는 추가 세이브포인트 없이 `run_briefings()` 를 그대로 부른다.
