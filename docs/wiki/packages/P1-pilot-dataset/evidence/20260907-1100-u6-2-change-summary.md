## 2. U6-5 — 새 규칙 (01-plan 90행 "판단 필요 3턴 규칙은 U6-2 에서 eval-agent 가 정해 03-log 에 남긴다")

> **U6-5.** 행위의 **한쪽이 사용자이면**(사용자→인물, 인물→사용자 어느 방향이든) 그 턴은 사용자–인물 사건이므로 활동 type 을 붙인다.
> type 은 — 꾸짖음·질책·불이익 = `conflict` / 사용자에게 이득이 되는 호의 = `favor` / 음식·음료 제공 = `meal` / 함께한 활동 = `meeting` / 칭찬 = `praise` / **마찰도 이득도 아닌 업무 지시·수업·과제 부과 = `other`**.
> 예외 둘: (i) **부작위** — "하지 않음"·"불이익을 주지 않음"(`굳이 말 안 했어`, `별말 안 하고 넘어갔어`, `그냥 넘어가주셨는데`)은 일어난 일이 아니므로 U6-3(f) 대로 이벤트가 아니다. (ii) **한 사건을 여러 턴에 나눠 서술하면 사건이 성립한 턴 하나에만** 붙인다(세부 묘사 턴은 이벤트 없음).
> 기존 규칙과의 관계: J(b) 미래 약속·계획, U6-1 인용형 호칭 진술, U6-3 성향·평판·상태 서술, U6-4 ambiguous 턴은 그대로 우선한다.

왜 이 규칙인가 — 이미 라벨된 sc-012 t2 `질문하러 갔다가 혼났어` = `conflict`(인물→사용자 질책), sc-004 t2 `불렀다가 혼남` = `conflict`, sc-007 t0 `피티 받았는데` = `other`, sc-029 t0 `자세 교정 받았어` = `other` 와 **같은 기준**이어야 하기 때문이다. J(d)("사용자–인물 사이 사건")가 방향을 말하지 않아 생긴 빈틈을 메운다(재검수 의견 절 마지막 불릿과 같은 취지).

## 3. 남은 판단 (검수자가 뒤집을 수 있게 적어 둔다)

1. **sc-012 t1 을 `favor` 로 볼 여지** — `넘어가주셨는데` 의 `-주다` 는 사용자를 위한 행위로 읽을 수도 있다. 그러면 같은 구조 sc-033 t2 도 favor 가 되어 이벤트가 2건 더 늘어난다. "이벤트는 실제로 일어난 일에만"(U6-3(f))을 더 무겁게 보아 **부작위 제외**를 택했다.
2. **sc-006 t2 의 주어 생략** — `주임님한테 인수인계 받으라고 했음` 의 지시 주체는 문면상 화자(사용자)다. 상사가 지시한 것으로 읽으면 인물→사용자 방향이 되지만, 어느 쪽이든 U6-5 상 `other` 라 라벨은 같다.
3. **sc-039 t1 `배달 기사님이 엘베 안 와서 계단으로 왔대`** — J(d) 글자대로면 전언 `personal_share` 가 될 수 있으나, t0(치킨 시켜줌)과 같은 배달 상황의 세부라 예외 (ii) 로 제외했다.
4. **sc-037 t2 `형이랑 술 마시면서 얘기 마니 했다`** — t0 meeting·t1 meal 과 같은 자리라 예외 (ii) 로 제외했다.

- **`other` 5건 / `personal_share` 26건(34%)**: U6-5 로 `other` 가 2 → 5 로 늘어 조금 나아졌으나 여전히 얇고, 다수 class 편향은 그대로다. P4 는 type 별 F1 과 함께 class 분포를 보고해야 한다.
