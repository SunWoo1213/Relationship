# FIX-009 · dev2 공유 푸시를 훅이 허용하게 한다

발견: 2026-09-29 · 사용자 지시("dev2에는 커밋마다 푸쉬를 해주세요") | Refs: FIX-009 security L-001 L-003

## 증상

사용자가 커밋마다 원격 `dev2` 에도 푸시하라고 지시했는데, `safety-guard.sh` 가 `origin dev` 와 승격용 `origin dev:main` 외의 모든 푸시를 거부해 에이전트가 `git push origin dev:dev2` 를 실행할 수 없었다. 그동안 dev2 푸시는 사용자가 `!` 로 직접 실행해 왔다(HANDOFF "사용자 몫" 항목).

브랜치 역할은 사용자가 2026-09-28 에 정했다: `main` = 최종 완성(배포), `dev` = 작업·백업, `dev2` = 다른 기기끼리 현재 상태 공유.

## 원인

L-001 브랜치 전략을 훅에 옮길 때 `dev2` 라는 갈래가 아직 없었다. 규칙은 "일상 푸시는 origin dev 로만, main 은 승격 절차로만" 두 갈래뿐이고 나머지는 전부 `deny` 로 떨어진다. dev2 는 나중에 생긴 용도라 그 `else` 에 걸린다.

## 수정안 (파일 · 방식 · 회귀 테스트)

`.claude/hooks/safety-guard.sh` — 푸시 분기에 `origin dev:dev2` 갈래를 추가한다. 설계 판단 세 가지:

1. **푸시 승인 마커를 요구하지 않는다.** `dev` 와 `main` 은 "이 내용을 올려도 되는가" 를 사람이 판단하는 자리라 마커가 필요하다. `dev2` 는 이미 승인받아 커밋된 내용을 다른 기기로 옮기는 백업이라 새 판단이 없고, 매번 마커를 요구하면 "커밋마다 푸시" 라는 지시와 어긋난다.
2. **방향을 `dev:dev2` 로 고정한다.** `origin dev2`(로컬 dev2 → 원격 dev2)는 허용하지 않는다. 작업 브랜치는 `dev` 하나이고, 뒤처진 로컬 dev2 에서 밀면 내용이 갈린다.
3. **강제 푸시 금지는 그대로다.** `--force` 검사가 분기보다 앞에 있어 `dev:dev2` 에도 그대로 적용된다.

`.claude/hooks/commit-cleanup.sh` — `dev:dev2` 푸시에는 L-003 대기 마커(`.claude/.awaiting-decision`)를 만들지 않고 `journal.md` 에 `PUSH-dev2` 줄만 남긴다. L-003 은 "dev 에 올렸으니 실서버 검증 후 승격 여부를 정하라" 는 장치인데, dev2 는 공유·백업이라 작업을 멈출 이유가 없다. 이 처리를 빠뜨리면 커밋마다 dev2 로 밀 때마다 다음 작업이 잠긴다.

문서: `docs/wiki/security.md` §2 와 `CLAUDE.md` 브랜치 전략 줄에 dev2 역할을 적는다.

**회귀 테스트(완료 판정 명령)** — `safety-guard.sh` 에 푸시 명령을 입력해 판정을 본다.

| # | 입력 | 기대 |
|---|------|------|
| 1 | `git push origin dev:dev2` | 통과(출력 없음) |
| 2 | `git push origin main` | deny |
| 3 | `git push origin dev2` | deny (방향 고정) |
| 4 | `git push --force origin dev:dev2` | deny |
| 5 | `git push backup dev:dev2` | deny (origin 아님) |
| 6 | 마커 없는 `git push origin dev` | deny (기존 규칙 유지) |
| 7 | 마커 없는 `git push origin dev:main` | deny (승격 규칙 유지) |
| 8 | 실제 푸시 후 | `.claude/.awaiting-decision` 미생성, journal 에 `PUSH-dev2` 줄 |

## 기획서 정합성

수정이 원칙·D·S 를 바꾸는가? **바꾸지 않는다.** `.claude/hooks/` 안에서만 일어나고 제품 코드·데이터 모델·툴 시그니처는 무변경이다. L-001(브랜치 전략)의 "작업·승인 푸시는 dev 로만, main 은 승격으로만" 은 그대로 살아 있고, dev2 라는 **백업 경로**가 하나 더해질 뿐이다. L-003(dev 푸시 후 대기)도 dev 에 대해서는 그대로다.
