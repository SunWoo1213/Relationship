# FIX-034 · 증거 저장 전용 통로 — 명령 출력 전체를 evidence 에 직접 쓰는 스크립트

발견: 2026-10-13 · P8-frontend U5 verifier 리뷰 R-U5-3(U3 R-U3-3 재발) — 사용자 결정 2026-10-13 "대책 (라), U6 앞에" | Refs: FIX-034 FIX-014 FIX-033 R-U3-3 R-U5-3 원칙8 L-002

## 증상

1. **증거 규칙 (c) "명령 출력 전체" 미달이 두 단위 연속 재발했다.** U3 구현자 변이 증거는 스크립트가 거른 줄뿐이었고(R-U3-3, `docs/wiki/packages/P8-frontend/evidence/20261012-1800-u3-mutation.txt` 머리글), U5 구현자는 변이 출력을 손으로 옮기며 M9·M10·M11·M13 의 stack·메시지를 줄였다(`20261013-1325-u5-mutation.txt` 머리글 자기 보고). 두 번 다 메인 세션이 스크래치패드 원본을 찾아 `-raw.txt` 로 보존해 증거 세트를 채웠다.
2. **verifier 판정(review-u5-chat.md §6)**: 재발이지만 원본이 있어 [권고]. 실질은 "근본 대책 선택". 대책 (가)~(라) 중 사용자가 **(라) 전용 저장 스크립트**를 골랐다.

## 원인

FIX-014 의 `bash-write-guard` 가 프로젝트 안 경로로의 Bash 쓰기(`>`·`tee`)를 막는다. 그래서 구현자·verifier 는 긴 명령 출력을 스크래치패드에 `>` 한 뒤 **자기 컨텍스트로 Read 해서 Write 툴로 옮겨 적어야** 한다. 수만 자를 모델이 옮겨 적는 구조 자체가 요약 압력이다(모델은 긴 반복 텍스트를 줄이려 한다). 규칙 문구((c), R-U3-3 "재발 시 [필수]")로는 구조를 못 이긴다. `bash_write_check.py` 모듈 docstring 의 한계 — "프로그램이 스스로 파일을 쓰는 것은 막지 않는다" — 를 **의도된 통로** 하나로 쓰면 수작업이 사라진다.

## 수정안 (파일 · 방식 · 회귀 테스트)

1. **새 스크립트 `.claude/scripts/save_evidence.py`** (Mac·Windows 공용 — 파이썬만, 셸 의존 없음; 이름은 기존 `*_check.py` 와 같은 밑줄 표기)
   - 호출: `python3 .claude/scripts/save_evidence.py <대상> <이름> [--append] [--note "<한 줄>"] -- <명령…>`
     - `<대상>`: 패키지 id(`docs/wiki/packages/<id>/` 가 있어야 함) 또는 `fixes`(→ `docs/wiki/fixes/evidence/`). 그 밖은 거부(exit 3).
     - `<이름>`: `[A-Za-z0-9._-]+` 만. 경로 구분자·`..` 거부(exit 3).
     - 파일: `<evidence 디렉터리>/<YYYYMMDD-HHMM>-<이름>.txt`. `--append` 면 같은 이름의 **가장 최근 파일** 끝에 구분선과 함께 덧붙인다(변이 루프용).
     - `<명령…>`: `--` 뒤 인자를 공백으로 이어 `bash -c` 로 실행(`cd web && npm test -- --run` 같은 한 줄). 작업 디렉터리는 저장소 루트. 환경에 `NO_COLOR=1`·`FORCE_COLOR=0`·`CI=1` 을 더한다(색·대화형 억제). stdout·stderr 를 **한 스트림으로 순서대로** 받는다(`stderr=STDOUT`).
     - 내용: 머리줄 5개(`# 명령:`·`# 시각:`·`# cwd:`·`# HEAD: <short> (<branch>)`·`# exit: <n>`) + `# ---` + 출력 **전체**(ANSI 이스케이프 `\x1b\[[0-9;?]*[A-Za-z]` 만 제거, 그 밖 바이트 무변경). 출력이 비어도 파일을 만든다.
     - **비밀 검사**: `secret-guard.sh` 의 PATTERNS 9개를 그대로 옮긴 정규식 목록으로 출력 전체를 검사. 걸리면 **파일을 쓰지 않고** 걸린 줄 번호와 패턴 이름만 stderr 에 내고 exit 2(값은 출력하지 않는다). 패턴 목록은 두 파일에 중복되므로 `save_evidence.py` 의 모듈 docstring 과 `secret-guard.sh` 주석에 "둘을 같이 고친다" 를 적는다.
     - 종료 코드: 저장 성공 시 **명령의 exit 코드를 그대로**(실패 테스트도 증거로 남고 호출자는 결과를 안다). 저장 실패(거부)는 2(비밀)·3(인자). stderr 에 저장한 경로를 한 줄 낸다.
     - 상한: 출력이 8 MB 를 넘으면 그대로 쓰되 머리줄에 `# 크기: <n> bytes (8 MB 초과)` 를 적는다(자르지 않는다 — 자르면 (c) 위반).
     - 테스트용 `--root <dir>`: evidence 뿌리를 그 디렉터리로 바꾼다(`test-guards.sh` 가 임시 디렉터리에서 돌리기 위함 — FIX-032 "자가 시험은 저장소를 건드리지 않는다"). `--root` 가 있으면 `<대상>` 존재 검사는 `<root>/<대상>/evidence` 기준.
2. **`.claude/scripts/test-guards.sh`** 에 "save_evidence" 절 13경우(① ~ ⑬, 재작업 1차 반영; 임시 디렉터리 `--root`): ① `echo hi` → 파일 생성·`# exit: 0`·본문 `hi`·종료 0 ② 명령이 exit 7 → 파일 생성·`# exit: 7`·종료 7 ③ 출력에 `sk-proj-` + 임의 영숫자 30자 → 파일 없음·종료 2 ④ `<이름>` 에 `../x` → 파일 없음·종료 3. 추가 ⑤ `--append` 두 번 → 파일 1개에 구분선 2개. 모두 Mac 에서 PASS, Windows 는 CI windows job(기존 단계)으로.
3. **문서 한 줄씩**: `docs/wiki/security.md` §4b 끝에 "증거 저장은 `save_evidence.py` 로 — 가드가 막지 않는 유일한 의도된 Bash 경유 쓰기, 비밀 검사 내장" · `docs/wiki/verification.md` "증거로 인정하는 것" 절에 "명령 출력은 `save_evidence.py` 산출물을 기본으로(머리줄 5개가 있는 파일)" · `.claude/agents/backend-agent.md`·`eval-agent.md`·`frontend-agent.md`·`verifier.md` 의 (c) 줄을 "증거는 `python3 .claude/scripts/save_evidence.py <패키지> <이름> -- <명령>` 으로 남긴다(출력 전체·exit·비밀 검사 자동). Write 로 옮겨 적지 않는다. 스크래치패드 사본에서 도는 변이 루프는 `--append` 로 변이마다 한 번" 으로 · `.claude/skills/devlog/SKILL.md` `/devlog fix` 5단계·`/devlog done` 1단계의 "스크래치패드 → Read → Write" 문구를 `save_evidence.py` 로.
4. **판정(실제 명령)**: `bash .claude/scripts/test-guards.sh`(새 5경우 포함 전부 PASS, 실패 0 skip 0) · `python3 .claude/scripts/save_evidence.py fixes fix034-selftest -- echo FIX-034-ok` 가 `docs/wiki/fixes/evidence/<ts>-fix034-selftest.txt` 를 만들고 그 파일에 `# exit: 0` 과 `FIX-034-ok` 가 있음 · `grep -c "save_evidence.py" .claude/agents/backend-agent.md .claude/agents/eval-agent.md .claude/agents/frontend-agent.md .claude/agents/verifier.md .claude/skills/devlog/SKILL.md docs/wiki/security.md docs/wiki/verification.md` 가 일곱 파일 모두 1 이상 · `python3 -m ruff check .claude/scripts/save_evidence.py` 통과 · CI windows job success.
5. **하지 않는 것**: `bash_write_check.py` 는 고치지 않는다(가드 규칙 무변경 — 이 스크립트는 "프로그램이 쓰는 것" 범주라 이미 통과한다). PostToolUse 재검사 없음(비밀 검사를 스크립트 안에 넣었으므로). 기존 증거 파일 이름·형식은 바꾸지 않는다.

## 재작업 1차 (verifier 1차 보류 `review-FIX-034.md` [필수] 3 · [권고] 6 → 사용자 결정 2026-10-13)

- **R-34-1 [필수] — 안쪽 명령 가드 검사(사용자 선택 (a), 가드 무변경)**: `save_evidence.py` 가 명령을 실행하기 **전에** `bash_write_check.py` 를 서브프로세스로 호출해(가드가 받는 것과 같은 JSON `{"tool_name":"Bash","tool_input":{"command":"<안쪽 명령 문자열>"}}` 을 stdin 으로) deny 면 실행하지 않고 stderr 에 가드 메시지를 그대로 내며 exit 3. 즉 `save_evidence.py fixes x -- 'echo x > app/y.py'` 는 가드와 같은 이유로 거부된다. test-guards 경우 추가: ⑦ 안쪽 명령 `echo x > app/y.py` → 파일 없음·exit 3 / ⑧ 안쪽 명령이 `/private/tmp/...` 임시 경로에 `>` → 허용(가드 규칙과 동일).
- **R-34-2 [필수] — `--append` 대상 선택**: 같은 이름 파일을 `^\d{8}-\d{4}-<이름>\.txt$` fullmatch 로만 고른다(접미사 겹침 금지). test-guards 경우 ⑨: `u5-mutation` 파일이 있어도 `mutation --append` 는 새 파일을 만든다.
- **R-34-3 [필수] — `--root` 범위**: `--root` 는 저장소 밖 임시 영역(`/tmp`·`/private/tmp`·`/var/tmp`·`tempfile.gettempdir()`·`$TMPDIR`)의 절대 경로만 허용, 저장소 안이면 exit 3. 대상 `.`·`..`·구분자 포함 거부. security.md §4b 의 "쓰기 범위 `docs/wiki/**/evidence/` 한정(테스트는 임시 영역 `--root`)" 문구와 맞춘다. test-guards 경우 ⑩: `--root <저장소> app` → exit 3·파일 없음.
- **R-34-4 [권고] — 시험 공백**: ③ 의 가짜 비밀을 **본문**(예: `printf` 로 출력)에 두는 경우 추가 ⑪ · stderr 순서 보존 시험 ⑫(`echo a; echo b >&2; echo c` → a b c 순) · 절단 금지 시험 ⑬(200 KB 출력 → 파일 크기 ≥ 200 KB).
- **R-34-5 [권고]**: 머리줄(명령 문자열·`--note`)도 ANSI 제거 뒤 비밀 검사·저장.
- **R-34-6 [권고]**: 같은 분 같은 이름 충돌 검사를 **명령 실행 앞**으로(2회째 출력 소실 방지).
- **R-34-7 [권고] 문서**: `verification.md` 63·86행 옛 "Read → Write" 문구 → 새 통로로 · 7곳 `python3` 고정 표기에 "(Windows 는 `python`)" 한 번 · `registry.md` 에 `save_evidence.py` 행 · 이 문서 수정안 2 "5경우" → 실제 경우 수.
- R-34-8 은 CI windows job 첫 실행으로 확인, R-34-9 는 생략.
- 판정 추가: `bash .claude/scripts/test-guards.sh` 새 경우 ⑦~⑬ 포함 실패 0 · 재검증은 review §5 방법(guard 11건·bypass ⑤-h·j·k·⑦·변이 mb·md·me·mf).
