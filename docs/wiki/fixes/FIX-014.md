> **상태: 착수(2026-10-11).** 2026-09-29 부터 운용 규칙(CLAUDE.md "파일 변경은 Write/Edit 툴로만")으로만 막아 왔으나 **실제로 뚫렸다**: P8-frontend U1 1차 구현에서 backend-agent 가 `app/api/read.py`·`schemas.py`·`routes.py` 를 heredoc·python 치환으로 썼다(자기 보고, `docs/wiki/packages/P8-frontend/review-u1-read-persons.md` R-U1-2 — 내용은 깨끗했음). 같은 날 메인 세션도 `HANDOFF.md` 를 `sed -i` 로 고치려다 auto mode 분류기에 막혔다. 운용 규칙만으로는 사람·에이전트 모두 지키지 못한다는 증거 → 사용자 결정 2026-10-11 "약점 해결 프로세스 시작", 방식은 아래 "결정".

## 증상

훅이 "무슨 일이 일어나는가" 를 툴 입력에서 읽는데, 그 읽는 층위가 실제 행위와 어긋나 **두 방향으로 다 틀린다.**

### 결함 ① 차단해야 할 것을 통과시킨다 — Bash 편집은 가드 넷을 지나간다

`stage-gate.sh`(28~34행)와 `secret-guard.sh`(22~23·44~52행)는 stdin 에서 `tool_input.file_path`(또는 `notebook_path`)와 `content`/`new_string`/`new_source`/`edits[].new_string` 만 뽑는다. **Bash 호출의 `tool_input` 에는 `command` 하나뿐이라 두 필드가 모두 비고, 두 훅은 첫 관문에서 `exit 0` 한다.**

| 실험 | 입력 | 결과 |
|------|------|------|
| 1 | Write 모양 + 개인키 머리말이 든 `content` | **deny** (secret-guard 정상) |
| 2 | **같은 내용**을 `cat > app/… <<EOF` heredoc 명령 문자열로 | **통과** (출력 없음) |
| 3 | `sed -i.bak s/a/b/ app/main.py` 를 stage-gate 에 | **통과** (출력 없음) |

실험 1 과 2 는 파일에 들어갈 내용이 글자 하나 다르지 않다. 툴 이름만 바뀌었다. 증거: `scratchpad/guardhole/demo.txt`(세션 임시 영역 — 착수 시 `docs/wiki/fixes/evidence/FIX-014/` 로 재생성한다).

`stage-gate.sh` 는 이름과 달리 **네 가지 규칙을 한자리에서 집행한다.** Bash 편집은 그 넷을 전부 지나간다:

1. **활성 작업 게이트**(76~99행) — 제품 코드는 `CURRENT.md active` + `02-plan-verify 결과: 통과` + `승인:` 이 있어야 쓴다
2. **기획서 동결**(70~74행) — `frozen: CR-nnn` 이면 제품 코드 쓰기 전면 차단
3. **L-003 dev 푸시 대기 잠금**(39~47행) — `.awaiting-decision` 이 있으면 HANDOFF·journal·초안·gitlog 외 쓰기 금지
4. **비밀 문자열 검사**(`secret-guard`, 키 패턴 9종)

`safety-guard.sh` 는 이것을 대신 잡지 못한다. 그 훅의 차단 범주 A~J(재귀 삭제·이력 파괴·푸시 승인·`git add` 경로·비밀 노출·원격 실행·권한·인프라 파괴·외부 전송·훅 우회) 중 "`sed -i` 로 `app/` 한 줄 고치기" 는 없다. 애초에 다른 목적의 훅이다.

**왜 이제 문제가 되는가:** auto mode 지침이 "파일 변경도 `sed`·heredoc 으로 하라" 고 지시한다. 즉 아무도 훅을 건드리지 않아도, **쓰는 툴이 바뀌는 것만으로** 가드가 열린다. FIX-008 과 같은 모양이다(그때는 macOS 에 `python` 이라는 이름이 없어 차단형 가드 5종이 조용히 열려 있었다).

### 결함 ② 일어나지 않은 일을 기록한다 — commit-cleanup 의 텍스트 매칭

`commit-cleanup.sh` 는 명령 **문자열**에 `git push origin dev2` 라는 글자가 있으면 푸시 갈래로 들어간다. 그 글자가 실행될 명령이 아니라 **다른 명령의 인자**여도 마찬가지다. 성공 판정(`origin/dev2 == HEAD`)이 우연히 맞아떨어지면 journal 에 가짜 줄이 남는다.

2026-09-29 실제 발생: FIX-013 검증 중 verifier 가 훅 사본에 넣을 명령 문자열을 인자로 담아 Bash 를 실행했고, 살아 있는 `commit-cleanup` 이 `- 2026-09-29 13:12 | PUSH-dev2 | origin dev2 0526f63 (실험 푸시)` 를 남겼다. **그 시각에 푸시는 없었다.** 메인 세션이 중복 줄임을 확인하고 지웠다.

지금은 journal 오염에 그치지만, 같은 텍스트 매칭이 마커 소비(`rm -f "$PUSH_MARK"`)와 L-003 잠금 생성(`.awaiting-decision`)에도 쓰인다. 조건이 맞으면 **승인 마커가 소비되거나 잠금이 잘못 걸릴 수 있다.**

## 원인

둘 다 뿌리가 같다 — **훅이 "행위" 가 아니라 "행위를 적은 문자열" 을 본다.**

- 결함 ①: 툴이 구조화 필드(`file_path`·`content`)로 주는 행위만 본다. 셸로 표현된 같은 행위는 안 보인다. **미탐.**
- 결함 ②: 셸 명령을 구조 없이 문자열로만 본다. 실행될 명령인지 인자인지 구분이 없다. **오탐.**

### 결함 ① — 새 PreToolUse(Bash|PowerShell) 판정 `bash-write-guard`

3. 쓰기 형태의 **대상 경로**가 판정 가능하면: 스크래치패드(`CLAUDE_SCRATCHPAD`/세션 임시 영역)·`/tmp`·`/private/tmp`·`$TMPDIR`·`/dev/null` → 허용. 그 밖(특히 `$CLAUDE_PROJECT_DIR` 안, 상대 경로) → **거부**하고 "Write/Edit 툴로 고쳐라(stage-gate·secret-guard 를 거치도록)" 안내.

5. **범위 밖(한계로 문서화)**: 파일을 쓰는 프로그램 실행 자체(`pytest`·`pip install`·`npm install`·`alembic upgrade`·`python scripts/x.py`·`git` 하위 명령·`bash .claude/scripts/*.sh`)는 막지 않는다 — 그건 "쓰기 문법" 이 아니라 도구의 정상 부작용이고, 막으면 개발이 멈춘다. 이 사각(스크립트 안에서 쓰기)은 남는다 → 운용 규칙 + verifier 리뷰가 계속 맡는다. npm scripts 간접 실행(P8 R-U0-3)도 같은 범주.
6. 오탐 대비: 허용 목록은 시험으로 고정한다(`git commit -F .claude/commit-draft.txt 2>&1`, `curl -o <스크래치패드>/x`, `pytest … | tee <스크래치패드>/out.txt`, `echo x >&2`, `cmd 2>/dev/null`, `grep a b > /tmp/x`).

### (참고) 착수 전에 검토했던 선택지

- **결함 ①의 방식.** `settings.json` 의 matcher 에 `Bash` 를 더하는 것만으로는 **아무 효과가 없다** — 두 훅이 `file_path` 가 없어 첫 줄에서 `exit 0` 하기 때문이다. 명령 문자열에서 쓰기 대상 경로를 뽑아야 한다: `>`·`>>` 리다이렉트, `sed -i`, `tee`, `cp`/`mv` 목적지, heredoc, `python - <<PY` 안의 `open(..., "w")`. 즉 **훅이 셸 문법을 파싱한다**는 뜻이다.
- **실패 방향.** 오탐이면 정상 작업이 막히고, 미탐이면 가드가 조용히 열린다. 이 저장소는 둘 다 겪었다(FIX-008 미탐, FIX-013 2차본은 고치려다 새 결함을 만들 뻔했다). 어느 쪽으로 기울일지 먼저 정한다 — `security.md` 의 기존 원칙은 "검사할 수 없으면 통과가 아니라 차단" 이다.
- **대안 검토.** 셸 파싱 대신 **Bash 로 파일 쓰기를 아예 거부**하는 안(경로 추출 없이 "쓰기로 보이는 Bash" 를 전부 막고 Write/Edit 로 유도)이 더 단순하고 실패 방향도 안전하다. 지금의 운용 규칙을 훅으로 승격하는 것에 해당한다. **이 안을 우선 검토할 것.**
- **결함 ②의 방식.** 명령 문자열을 `;`·`&&`·`||`·`|` 로 쪼개 **첫 토큰이 `git` 인 조각**만 판정 대상으로 삼는 안. `safety-guard.sh` 가 이미 `[^;|&]*` 로 구간을 끊어 보는 전례가 있다(68~85행).
- **회귀 테스트.** `test-guards.sh` 에 붙인다. FIX-013 이 배운 것을 반드시 적용한다 — **고치기 전 훅에서 새 시험이 실패하는지(검출력)를 고치기 전에 확인한다.** 통과만 하는 시험은 회귀를 못 잡는다.
