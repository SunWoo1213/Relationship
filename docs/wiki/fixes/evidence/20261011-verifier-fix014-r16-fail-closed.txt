## 2. (?:Sync)? 정규식 — 필요한가·무해한가 (python3 -c 로 옛/새 패턴을 같은 코드에 대고 비교)
old = \b(…|Bun\.write|Deno\.writeTextFile|Deno\.writeFile)\s*\(
new = \b(…|Bun\.write|Deno\.writeTextFile(?:Sync)?|Deno\.writeFile(?:Sync)?)\s*\(   ← 현재 bash_write_check.py 906~907행

Deno.writeTextFileSync("app/x","")            old=False new=True  new.group=Deno.writeTextFileSync
Deno.writeTextFile("app/x","")                old=True  new=True  new.group=Deno.writeTextFile
Deno.writeFileSync("app/x",b)                 old=True  new=True  new.group=Deno.writeFileSync
require("fs").writeFileSync("app/x","")       old=True  new=True  new.group=writeFileSync
fs.copyFileSync("a","b")                      old=True  new=True  new.group=copyFileSync
Deno.readTextFileSync("app/x")                old=False new=False new.group=None

판독:
- 필요: 옛 패턴은 `Deno.writeTextFileSync(` 를 잡지 못한다(`\s*\(` 가 `Sync` 앞에서 끊김). 이것이 R-14-16 의 핵심 케이스(V14-3 `printf "Deno.writeTextFileSync(…)" | deno run -`)의 쓰기 API 이므로, 이 1줄 없이는 서브명령 처리를 고쳐도 V14-3 이 allow 로 남는다 → 지시 밖 변경이지만 R-14-16 을 닫는 데 필요하다.
- 참고(정정): `Deno.writeFileSync` 는 옛 패턴에서도 이미 잡혔다(`writeFileSync` 대안이 `\b` 뒤에서 매칭) — FIX-014.md 125행 "`Deno.writeTextFileSync`·`Deno.writeFileSync` 를 놓치던 것" 은 앞의 것만 맞다. 동작에는 영향 없음.
- 무해: `(?:Sync)?` 는 Deno 두 이름에만 붙고 다른 대안(writeFile/writeFileSync/copyFile…/Bun.write)은 글자 그대로. 읽기 API(`readTextFileSync`)는 매칭되지 않는다. 라이브 훅 20건 회귀(variants "## (?:Sync)? 회귀") 불일치 0.
