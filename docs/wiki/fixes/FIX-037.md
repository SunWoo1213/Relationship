## 원인

로그인(P9b)과 무관하다 — `git diff d9c5a5f..HEAD` 에서 `propose.py`·`gate.py`·`respond.py`·`app/er/` 는 0줄.

1. **인식 프롬프트의 의도 정의가 부실하다**(`app/agent/propose.py:245-247`). "이미 기록된 인물 정보를 묻는 질문이면 query … 둘이 섞이면 query" 만 있고, 묻는 형태가 아닌 평서문은 record 라는 말이 없다. 평서문 8회 중 5회는 기록 도구를 맞게 제안했는데 의도가 query 라 `query_turn_no_write`(`gate.py:113`)로 버려졌다.
2. **이벤트 유형 7종에 설명이 없다**(`propose.py:140`). 사실 키 9종은 설명이 있다(`FACT_KEY_DESCRIPTIONS`, FIX-017). 유형 enum 은 함수 스키마에 `strict` 가 없어 강제되지 않으므로 `health` 같은 값이 새어 나온다.
3. **조회 답 프롬프트가 근황 질문을 평가 질문으로 읽는다**(`app/agent/respond.py:155-163`). "평가·조언·감정 대화는 하지 않는다 … 자료에 없는 것은 '기록이 없어요'" 만 있고, "요즘 어때?" 를 최근 기록의 재진술로 답하라는 말이 없다. (모델 내부 이유는 가설, 문형별 재현이 근거.)
4. **거부된 기록을 사용자에게 알리지 않는다**(`respond.py:77`). 제안이 없던 턴과 제안이 형식 오류로 버려진 턴이 같은 문장을 쓴다.

측정된 적 없는 영역이다: 의도 분류·이벤트 유형 정확도는 P10 으로 인계돼 있고 P10 은 미착수, `reports/metrics.json` 은 인물 해석(ER) 전용이다.

## 수정안 (파일 · 방식 · 회귀 테스트)

### 0. 먼저 재는 표본을 만든다 (eval-agent, 코드 수정 전)
- `evaluation/recognition/heldout.jsonl` — 한국어 발화 30건 안팎. **시연 발화 13개의 문장·인물 이름을 쓰지 않는다**(원칙 8, 과적합 금지). 구성: 평서 사실·근황 약 8, 사건 약 14(유형 7종 고루, 그중 "회의·식사 자리에서 생긴 갈등" 같은 겹치는 경우 포함), 실제 질문 약 6(근황 문형 포함), 사건+사실 혼합 약 2. 라벨: `intent`, 기대 도구(`add_event`/`update_person`/`add_schedule`/없음), 기대 `type`.
- `evaluation/recognition/probe.py` — 로컬 서버에 새 시험 계정으로 발화를 넣고 `agent_traces` 의 `loop_extract`·`loop_gate` 를 읽어 발화별 결과를 모은다(조사 때 쓴 스크래치패드 `extract-quality/probe.py` 방식). 발화마다 **5회**. 칩에는 답하지 않는다(저장 0).
- 조회 답 표본: 사건이 3건 이상 있는 시험 계정 카드에 근황 문형 4개 + 기록에 없는 것을 묻는 문형 2개, 각 3회.
- 산출: `reports/recognition-probe.md` 에 **수정 전** 수치(의도 일치율, 유형 일치율, enum 이탈 수, 근황 질문 답변율, 없는 것을 물었을 때 "기록이 없어요" 비율).

### 1. 인식 프롬프트 (`app/agent/propose.py`) — backend-agent
- 의도: "묻는 형태(의문형·물음표·알려 달라는 요청)일 때만 query, 인물에 대해 알려 주는 평서문은 record" 를 명시한다. "둘이 섞이면 query" 는 그대로 둔다(D16 결정 6).
- 이벤트 유형: 7종 각각 한 줄 설명과 겹칠 때의 우선순위를 넣는다 — 다툼·언쟁·지적받음·부딪힘은 회의·식사 자리였어도 `conflict`, 도움을 주고받음은 `favor`, 칭찬·인정은 `praise`, 본인 신상·근황을 털어놓음은 `personal_share`, 어느 것도 아니면 `other`. "이 7개 밖의 값을 쓰지 마라" 를 넣는다. 설명은 `FACT_KEY_DESCRIPTIONS` 처럼 상수로 두고 프롬프트가 그 상수에서 만들어지게 한다.
- 한 발화에 사건과 인물 사실이 함께 있으면 둘 다 제안하라고 넣는다.
- 프롬프트 예시에 시연 발화 문장을 쓰지 않는다.

### 2. 조회 답 프롬프트 (`app/agent/respond.py:155-163`) — backend-agent
- "요즘·최근·어때·근황처럼 근황을 묻는 질문에는 자료의 최근 사건·일정을 날짜와 함께 그대로 재진술하라" 를 넣는다. 평가·조언·감정 금지와 "자료에 없는 것은 '기록이 없어요'" 는 그대로 둔다.

### 3. 거부 알림 (`app/agent/respond.py`) — backend-agent
- 기록 턴에서 저장된 것이 없고 게이트가 기록 제안을 `bad_args` 로 버린 경우에만 문장을 바꾼다: `"말씀하신 내용을 기록하지 못했어요. 다시 한 번 말씀해 주시겠어요?"`. 제안 자체가 없던 턴은 지금 문장 그대로.
- 형식이 틀린 유형을 `other` 로 고쳐 저장하는 보정은 **하지 않는다**(게이트 규칙 추가 — 사용자 결정 사항으로 남긴다).
