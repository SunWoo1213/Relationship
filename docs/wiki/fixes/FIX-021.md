커밋: pending(backend-agent 는 커밋하지 않음 — 메인 세션이 `/commit` 으로 처리)

**1~2. 의존성·ruff 설정** — `requirements-dev.txt` 에 `ruff==0.16.10`·
`pytest-cov==7.1.0`·`mypy==2.4.0` 고정(`pip check` No broken requirements).
신규 `pyproject.toml` -- `[tool.ruff.lint] select = ["F","B","DTZ"]`,
`[tool.ruff.lint.flake8-bugbear] extend-immutable-calls`에 `fastapi.Depends`·
`Query`·`Path`·`Body` -- 이걸로 B008 오탐 15건(FastAPI 관례)이 전부

`tests/conftest.py` 동작 무변경 확인 -- 전체 회귀 통과로 검증).

**3. 실문제 수정(app/tests/scripts/evaluation)**:
- F821 `tests/test_agent_loop.py` -- `GateVerdict` 를 `app.agent.types` 에서
  정식 import(기존엔 따옴표 forward-ref 로 가려져 있었다).
- B017 블라인드 예외 3곳 -- `GeminiBriefingComposer` 미설정 테스트는
  `InvalidValue`(실제로 던지는 타입, `app/briefing/compose.py`
  `__post_init__` 확인)로, `PersonSpec`/`ScenarioState` 두 frozen
  dataclass 속성 재할당 테스트는 `dataclasses.FrozenInstanceError`(실측
  확인)로 좁혔다 -- 더 강한 단언이 됐다(이전엔 임의 예외도 통과).
- DTZ 5건 -- `scripts/dump_scenarios.py` 의 파일명 타임스탬프 1건은 실제
  수정(`datetime.now()` → `.astimezone()`, 벽시계 값은 그대로 두고
  tz-aware 로만 만든다 -- 출력 파일명 불변 확인). 나머지 4건(`test_agent_
  loop.py`·`test_tools_questions.py`·`test_tools_records.py` 2곳)은 함수
  이름·주석으로 이미 "naive 거부 경로 자체를 시험한다" 는 의도가 분명해
  줄 단위 `# noqa: DTZ001 # 이유` 로 남겼다(동작 무변경).
- B905(zip strict 미지정) 15건(app 1 · tests/scripts/evaluation 14) -- 전부
  호출부를 직접 확인해 `strict=True`/`False` 를 명시했다. 대부분(13건)은
  길이가 이미 보장돼 있었다(모듈 레벨 assert·직전 guard·같은 리스트에서
  파생) -- `strict=True` 가 그 보장을 코드로 드러낸다. `evaluation/
  curve.py` 의 `zip(keys, keys[1:])` 1건만 의도된 슬라이딩 윈도(길이가
  항상 1 다름)라 `strict=False`. `scripts/backfill_embeddings.py` 의
  `zip(batch, vectors)` 1건은 이전엔 길이 검사가 전혀 없어 **실제
  안전장치 추가**(provider 반환 벡터 수가 배치와 다르면 전엔 조용히
  잘못된 별칭에 엉뚱한 벡터가 쓰였을 수 있다 -- 이제 즉시 예외).
- F841(미사용 `schedule` 2건)·F541(불필요 f-prefix 2건)·F401(미사용 `os`)·
  F402(`text` 섀도잉 -- `alias_text` 로 개명)·B007(미사용 루프 변수 `i` →
  `_i`) -- 전부 기계적 정리, 동작 무변경.

**4. mypy 실제 결함 후보 3건** -- 셋 다 **narrowing-only**(실제 None/타입
불일치 경로 없음, 표기 문제)로 판정했지만, 그 중 하나(`compose.py:468`)는
방어 코드 추가가 실질적인 견고성 개선이라 회귀 테스트를 달았다:
- `app/tools/persons.py:212` -- `embedding_ran = provider is not None and
  ...` 를 거친 `if embedding_ran:` 블록에서 mypy 가 `provider` 를 좁히지
  못했다. `if provider is not None and embedding_ran:` 로 조건에 `is not
  None` 을 반복해 narrowing(동작 동일, 실측: 같은 블록 재진입 조건).
- `app/tools/persons.py:388` -- `session.get(PersonAlias, inserted_id)` 의
  반환 타입이 `PersonAlias | None`. 같은 세션이 방금 `RETURNING` 으로 받은
  id 라 삭제 없음 불변(D6)상 None 일 수 없다(실제 결함 아님) -- 하지만
  조용히 None 을 돌려주면 호출자가 더 혼란스러운 `AttributeError` 를 다른
  곳에서 받는다. `assert` 대신 명시적 `if inserted is None: raise
  RuntimeError(...)` 로 방어하고 불변이 적힌 이유를 남겼다(P7 U4 교훈 --
  런타임 assert 회피).
- `app/briefing/compose.py:468` -- `generated_by_key[key] = sentence` 에서
  `key: Any | None` 을 `dict[str, str]` 키로 썼다. `_parse_composed` 를
  거치면 항상 비어있지 않은 str 이지만, `validate_briefing()` 은 `raw:
  ComposedBriefing` 을 직접 받을 수도 있어(테스트가 그렇게 한다) 그 경로를
  보장하지 않는다. **실측으로 확인**: 고치기 전 `key` 가 해시 불가능한
  값(예: list)이면 `key not in allowed_pattern_key_set` 에서 바로
  `TypeError` 가 나 이 함수의 docstring 약속("예외를 던지지 않는다")이
  깨졌다 -- `isinstance(key, str)` 가드를 추가해 좁히기 + 실제 결함을
  같이 고쳤다. 회귀 테스트
  `test_validate_briefing_rejects_pattern_sentence_with_unhashable_key`
  추가, 고치기 전 되돌려 `TypeError: cannot use 'list' as a set element`
  로 실패함을 확인한 뒤 복구(증거 참고).
