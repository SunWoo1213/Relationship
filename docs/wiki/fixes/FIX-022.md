# FIX-022 · CI 에서 Python 두 버전과 Windows, 훅 자가 점검까지 확인한다

발견: 2026-10-05 · 테스트 방식 점검 ⑤ → 2026-10-06 FIX-021 CI 실패(run 37397329951)로 실제로 드러남 | Refs: FIX-022 FIX-008 FIX-010 FIX-011 FIX-021 원칙8

## 증상

- CI 는 Python 3.13, 로컬 Mac `.venv` 는 3.14.7. FIX-021 의 mypy 기준선이 이 차이(typeshed 문구) 때문에 CI 에서만 실패했다 — 버전 차이는 이미 실제 결함으로 나타났다.
- "Mac·Windows 양쪽에서 동작" 이 명시 요구인데(FIX-008·010·011) Windows 확인은 HANDOFF 에 계속 **[미확인]**. CI 는 ubuntu 하나뿐.
- 훅 자가 점검 `.claude/scripts/test-guards.sh`(로컬 약 6초, 실패 0 이면 exit 0)는 사람이 손으로 돌릴 때만 실행된다.
- DB 없이 `pytest -m "not dbtest"` → `1377 passed, 9 skipped, 423 deselected`(2026-10-06 로컬, `POSTGRES_PORT=1`) — DB 를 쓰면서 `dbtest` 표시가 빠진 테스트 9개가 skip 으로 남는다(Windows 러너는 Postgres 서비스 컨테이너를 쓸 수 없어 이 경로가 필요하다).

## 원인

CI 를 처음 만들 때(P1) 리눅스·한 버전·pytest 만 대상으로 했고, 이후 크로스플랫폼 요구(FIX-008)가 생겼지만 CI 는 따라가지 않았다.

### 고치지 않고 보고만 하는 것 (test-guards.sh 의 CI 위험 지점)

- `.claude/hooks/_py.sh` 의 `HOOK_PY` 탐지는 `command -v python`/`python3` 가 **실제로 실행되는지**로 판정한다. `actions/setup-python` 이 선택한 버전에 대해 `python` 심볼릭 링크를 PATH 에 놓는지는 이번에 직접 확인하지 못했다(로컬에서는 재현 불가) — CI 에서 처음 드러날 수 있는 지점이다.
- `test-guards.sh` 의 "에이전트 frontmatter YAML 파싱" 절은 PyYAML 이 되는 인터프리터를 찾아야 하는데, `requirements-dev.txt` 에 PyYAML 이 없고 CI 에는 `.venv` 도 없다 — 실패가 아니라 `skip frontmatter 검사`로 조용히 넘어간다(로컬 실행에서도 동일하게 확인됨, 이 자체는 회귀가 아니라 기존부터 있던 커버리지 공백이다).
- `test-guards.sh` 의 "stage-gate" 절 일부(`active: none` 분기)는 `docs/wiki/CURRENT.md` 의 현재 `active` 값에 좌우된다. 지금은 `P7-push` 라서 그 분기가 `skip active=P7-push` 로 건너뛰어진다 — CI 결과가 그 시점의 프로젝트 상태에 따라 검사 범위가 달라진다는 뜻이며, 스크립트 결함은 아니다.
