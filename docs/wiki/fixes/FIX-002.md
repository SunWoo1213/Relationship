# FIX-002 · 게이트 검사가 CR-001 이전에 멈춰 있어 P5 이후가 전부 막힌다

발견: 2026-09-23 · P5-loop 계획 기계 검증(`verify-plan.sh P5-loop`) | Refs: FIX-002 P5-loop CR-001 원칙8

## 증상

`bash .claude/scripts/verify-plan.sh P5-loop` 이 FAIL 을 낸다. 게이트는 실제로 통과했는데 스크립트가 모른다.

```
FAIL  P4 게이트 미통과: P5 이후는 P4-pilot-eval 완료 전에 시작할 수 없다
```

증거: `docs/wiki/packages/P5-loop/evidence/20260923-1508-verify-plan.txt` (소견 `F-4e4fe4` [필수]).

이 검사는 패키지 번호가 5 이상이면 **전부** 걸리므로 P5·P6·P7·P8·P9·P10·P11 이 같은 FAIL 을 낸다. 한 패키지의 문제가 아니다.

## 원인

`.claude/scripts/verify-plan.sh` 68~72행이 게이트 패키지 경로를 **문자열로 박아 두었다**.

```bash
num="$(printf '%s' "$id" | sed -E 's/^P([0-9]+)-.*//')"
if [ "$num" -ge 5 ] 2>/dev/null; then
  g="$W/packages/P4-pilot-eval/04-review.md"
  if [ -f "$g" ] && grep -Eq '^결과:[[:space:]]*완료' "$g"; then ok "P4 게이트 통과"; else bad "..."; fi
fi
```

그런데 `P4-pilot-eval/04-review.md` 는 `결과: 부분완료` 다. **실제로 게이트에 미달했기 때문이고**(`0.8 ['embedding_only'] True False`), 원칙8("성능 미달도 결과다. 데이터셋·라벨·베이스라인을 조작하지 않는다")대로 그 기록을 고치지 않고 닫았다.

게이트를 통과한 것은 CR-001 이 만든 **`P4b-er-redesign`** 이다 — `04-review.md` `결과: 완료`, `0.8 [] True True`, 사용자 승인 2026-09-23(`1075dd6`).

문서 쪽은 이미 갱신돼 있다. `docs/wiki/INDEX.md` 81행:

> **P4 이전에 P5 이후를 시작하지 않는다**(P4 미달 → P4b 게이트 통과가 조건, CR-001). 한 번에 활성 패키지는 하나.

즉 **CR-001 이행에서 문서는 바꿨는데 스크립트를 빠뜨렸다.** `grep -rn "P4-pilot-eval" .claude/scripts/ .claude/hooks/` 결과 하드코딩은 이 한 곳뿐이다(`verify-plan.sh` 70·71행). `verify-impl.sh` 에는 같은 검사가 없다.

## 기획서 정합성
수정이 원칙·D·S 를 바꾸는가? **바꾸지 않는다.** CR-001 이 이미 확정한 규칙(게이트는 P4b)을 스크립트가 따라가는 것뿐이고, 기준을 낮추는 것이 아니다 — 여전히 **04-review 가 `결과: 완료`** 여야 통과한다.

- 점검표 1(범위): 침범 없음 — 하네스 스크립트 한 줄기
- 점검표 2(불변 원칙): **원칙8 을 지키기 위한 수정이다.** 대안 (c)"P4 문서를 완료로 고친다"는 미달 기록을 조작하는 것이라 명시적으로 배제했다(사용자 결정 2026-09-23)
- 점검표 3·4(D·S 카드): 충돌 없음. D/S 카드를 고치지 않는다
- 점검표 8(보안): 비밀·외부 전송·삭제 없음. 가드를 **약화하지 않는다** — 통과 조건을 넓힌 것이 아니라 CR-001 이 옮긴 대상을 가리키게 한 것이다

검증: 통과
승인: 사용자 (2026-09-23) — 게이트를 P4/P4b 둘 중 하나로 넓히되 기준(04-review 결과: 완료)은 그대로. test-guards.sh 옛 경로 13곳은 보고만 받고 별도 단위로 미룬다는 결정도 함께.

## 결과 (커밋 해시 · 테스트)

- **1단계** `bash -n .claude/scripts/verify-plan.sh` → 문법 오류 없음.
- **2단계** `bash .claude/scripts/verify-plan.sh P5-loop` → **`PASS  P4 게이트 통과 (P4b-er-redesign)`**. 전체는 `FAIL=1 WARN=7` 로 줄었다(수정 전 `FAIL=12 WARN=7`). 남은 FAIL 1 은 `02-plan-verify.md` 없음 — verifier 가 다음 단계에서 쓰는 문서라 이 시점에 없는 것이 정상이다. 증거 `docs/wiki/packages/P5-loop/evidence/20260923-1518-verify-plan-2.txt`.
- **3단계 부정 확인** — 게이트 블록만 떼어낸 사본을 scratchpad 의 가짜 트리에 물려 돌렸다. 가드가 **약해지지 않았다**:

  | 상황 | 결과 |
  |---|---|
  | 두 04-review 가 아예 없음 | `FAIL  P4 게이트 미통과...` |
  | P4 가 `부분완료`(지금의 실제 상태) | `FAIL  P4 게이트 미통과...` |
  | P4·P4b 둘 다 `부분완료` | `FAIL  P4 게이트 미통과...` |
  | P4b 가 `완료` | `PASS  P4 게이트 통과 (P4b-er-redesign)` |
  | 패키지 번호가 5 미만(`P3-er`) | 출력 없음(이 검사를 하지 않는다) |

- **4단계** `bash .claude/scripts/test-guards.sh` → `== 결과: 실패 2 ==`. **이 둘은 이 수정과 무관한 기존 결함이다.** 실패한 것은 `stage-gate` 검사 두 개(`product code with active: none`, `awaiting: plan doc denied`)이고 `verify-plan` 검사는 `ok` 다. 원인: **`test-guards.sh` 가 옛 프로젝트 경로 `C:\Capstone2` 를 13곳에 박아 두었다.** 저장소가 `C:/Portpolio/Project_Relationship` 로 옮겨진 뒤 그 경로는 stage-gate 가 보기에 "프로젝트 밖"이라 면제되고, 테스트는 그것을 실패로 센다. **가드 자체는 정상이다** — 같은 판정을 실제 경로로 돌리면 차단한다:

  | 입력 | stage-gate 판정 |
  |---|---|
  | `C:\Portpolio\Project_Relationship\app\main.py` (`active: none`) | **deny** |
  | `C:\Capstone2\app\main.py` | allow (프로젝트 밖) |
  | `C:\Portpolio\Project_Relationship\docs\wiki\x.md` | allow (docs 면제) |

  주의: 이 훅은 `deny()` 가 JSON 을 출력하고 **exit 0** 하므로 종료 코드가 아니라 **출력**을 봐야 한다. 처음에 종료 코드로 판단해 "가드가 안 막는다"고 잘못 읽었고, 출력을 보고 정정했다.
- **남긴 것(별도 처리)**: `test-guards.sh` 의 옛 경로 13곳을 현재 루트로 바꾸는 일은 **이 FIX 의 범위 밖**이다. 게이트 검사와 성격이 다르고, 고치면 지금 숨어 있는 다른 실패가 드러날 수 있어 별도 단위로 봐야 한다. 사용자 보고 항목으로 올린다.
