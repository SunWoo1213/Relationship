# FIX-001 · main 이 dev 와 갈라져 승격할 수 없다 — origin/main 을 dev 로 병합한다

## 증상

`git push origin dev:main` 이 거부된다. `/commit release` 는 fast-forward 만 허용하는데 두 브랜치가 갈라져 있다.

충돌은 `README.md` **1건**뿐이다. 나머지 4파일은 dev 에 없거나 겹치지 않아 자동 병합된다.

## 원인

L-001 은 "작업·푸시는 `dev` 로만, `main` 은 배포 브랜치"이고 훅은 **dev 이외로의 푸시**를 막는다. 그러나 위 6커밋은 dev 를 거치지 않고 `main` 에 직접 올라갔다 — 훅은 이 세션의 `git push` 만 검사하므로 **다른 경로(웹 UI·다른 클론·다른 도구)로 main 에 올라간 커밋은 잡지 못한다**. 그래서 main 이 dev 보다 앞서는 상태가 만들어졌고 fast-forward 가 깨졌다.

`README.md` 가 충돌하는 이유는 양쪽이 같은 파일을 서로 다른 목적으로 고쳤기 때문이다 — main 쪽은 소개·설계 과정 전면 보강(254줄), dev 쪽은 진행 상태 표의 P4·P4b 행과 "파일럿 평가 실행법" 절 추가(28줄).
