# FIX-036 · 실제 배포 뒤 로컬에 생긴 Terraform 상태 파일 때문에 인프라 파일 검사 테스트가 실패한다

## 원인

- 테스트 27(`tests/test_infra_files.py:427-435`)은 **작업 트리**의 `infra/` 에 `.tfstate`·`.tfvars` 이름이 있으면 실패한다. docstring 의 전제는 "에이전트는 apply 한 적이 없다".
- 2026-11-15 사용자가 `terraform apply` 를 직접 실행했다(security §4 — apply 는 사용자 몫, P9-infra U4). 그 결과 로컬에 `infra/terraform.tfstate` 가 생겼다. 이 파일은 `.gitignore:46 infra/*.tfstate` 로 막혀 있어 커밋되지 않고, 2026-11-19 `terraform destroy` 에 필요하므로 지우면 안 된다.
- 즉 테스트가 지키려는 것(상태·변수 파일이 **저장소에 들어가지 않는다**)과 검사하는 것(작업 트리에 파일이 **없다**)이 달라, 정상 배포 뒤에는 이 기기에서 항상 실패한다. CI 는 새 체크아웃이라 통과한다.

## 수정안 (파일 · 방식 · 회귀 테스트)

- `tests/test_infra_files.py` 테스트 27 만 고친다(제품 코드 `app/`·`alembic/`·`web/` 무변경).
- 방식: 작업 트리 대신 **git 이 추적하는 파일**(`git ls-files infra`)에 `.tfstate`·`.tfvars`(`terraform.tfvars.example` 제외)가 없음을 단언한다. 그리고 작업 트리에 그런 파일이 실제로 있으면 그 파일이 **ignore 되고 있음**(`git check-ignore`)을 단언한다 — 없으면 이 부분은 건너뛰지 않고 "없음" 으로 통과.
- 함수 이름은 뜻이 바뀌므로 `test_no_state_or_vars_files_are_tracked_by_git` 로 바꾸고 docstring 을 사실에 맞게 고친다. 이름을 참조하는 문서(`packages/P9-infra/tests.md` 등)는 grep 해서 함께 고친다.
- 회귀: `.venv/bin/python -m pytest tests/test_infra_files.py -q` 전부 통과, 전체 pytest 실패 0. 변이: 임시 저장소 사본에서 `infra/x.tfstate` 를 `git add -f` 한 상태로 테스트가 실패하는지(저장소 무수정).
