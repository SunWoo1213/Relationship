1. **F-46f1eb** — 테스트 3곳이 가짜 키를 `sk-` 로 시작하는 문자열로 넣는다. 다른 테스트 파일은 `_FAKE_KEY_MARKER = "FAKE-TEST-ONLY-NOT-A-REAL-KEY-4f21"` 을 쓴다. 규약이 둘이고, 비밀 검사기가 진짜 키로 오인할 수 있다.
2. **F-036185** — `app/er/judge.py` `validate_judgement` 는 `isinstance(matched_person_id, int)` 로만 검사한다. 파이썬에서 `True` 는 `int` 이므로 `True` 가 통과하고, `True in {1}` 이 참이라 1번 후보로 귀속될 수 있다. 실호출은 strict 스키마가 막지만 방어가 없다. 잘못 귀속되면 오병합이다(원칙1).
3. **F-c7078e** — `alembic/script.py.mako` 가 docstring 에 `Refs: P1-schema …` 를 고정했다. 다음에 `alembic revision` 으로 만드는 파일이 모두 P1-schema 태그를 갖게 되어 `git log --grep` 추적이 틀어진다. 지금 revision 은 `0001` 하나뿐이라 아직 오염은 없다.

1. P3-er U5 가 더미 키를 넣을 때 secret-guard 훅이 반응하지 않아 U2·U8 의 마커 규약을 따르지 않았다. 이후 P5-loop 의 `test_agent_propose.py` 가 같은 표기를 복사했다.
