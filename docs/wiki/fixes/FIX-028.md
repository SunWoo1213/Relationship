## 원인 (가설 — Windows 기기가 없어 로컬 재현 못 함, 구현 단계에서 CI 로 확정)

- 실패한 4건은 모두 `SG_T="$(mktemp -d)"` 임시 저장소를 쓴다. Git Bash 의 `mktemp -d` 는 `/tmp/tmp.xxx` 같은 MSYS 경로를 준다.
- `gate()` 는 그 경로를 **Windows 네이티브 python** 인자로 넘겨 JSON 을 만든다 → MSYS 가 인자를 `C:/Users/.../Temp/tmp.xxx/...` 로 자동 변환한다. 반면 `CLAUDE_PROJECT_DIR="$SG_T"` 는 환경변수라 `/tmp/tmp.xxx` 그대로(또는 다른 형태) 훅에 들어간다.
- `stage-gate.sh` 의 경로 정규화(45~61행)는 `/c/...` ↔ `C:/...` 만 맞춘다. `/tmp/...` 는 맞추지 못해 대상 파일을 "프로젝트 밖" 으로 보고 `exit 0`(allow) 한다.
- 실제 저장소 경로는 `/d/a/...` 형태라 정규화가 맞아 통과한다 — 증상과 일치.
- **파생 위험**: 같은 `SG_T` 방식을 쓰는 "allow 기대" 시험(FIX-027 의 `F-27-1` 새·옛 템플릿 2건 등)은 Windows 에서 "프로젝트 밖이라 allow" 로 **공허하게 통과**했을 수 있다. FG_T 등 다른 격리 저장소 시험도 같은 경로 변환을 타는지 확인이 필요하다.
- 실사용 영향: Claude Code 가 Windows 에서 훅에 주는 `CLAUDE_PROJECT_DIR`·`file_path` 의 실제 형태는 미확인. 정규화가 실사용 형태도 덮는지 구현 단계에서 확인해 기록한다(못 하면 "미확인"으로 남긴다).

## 결과 (커밋 해시 · 테스트)

구현 완료(미커밋, verifier 리뷰 대기). 변경 파일:
- `.claude/scripts/test-guards.sh` — (A) `native_path()` 헬퍼(`cygpath -m` 있으면 사용, 없으면 원값 → Mac 무변경)를 `mktemp -d` 로 만드는 4곳 전부(FG_T, SG_T 2곳, CC_T)에 적용. (C) 대조 3건: FG_T 마커 없는 커밋 DENY, SG_T(F-27-1 절)·SG_T(R-27-5 절) 각각 `active: none` 에서 `app/x.py` 쓰기 DENY — 실패하면 공허 통과로 보고 실패로 센다.
- `.claude/hooks/stage-gate.sh` — (B) `cygpath` 가 있을 때만 `fp`·`root_fwd` 를 `cygpath -m` 으로 맞춘다. `/` 로 시작하는 절대경로만 변환, 실패 시 원값 유지, 거부/허용 규칙·JSON 출력 무변경. 다른 훅은 경로 비교를 하지 않아 보강 불필요: `commit-guard.sh` 는 `ROOT` 로 파일을 읽을 뿐이고 `fix_guard_check.py` 는 `ROOT` 를 인자로 받아 열기만 한다(비교 없음).
- 가설의 코드 근거: 수정 전 `stage-gate.sh` 정규화는 `\`→`/` 와 `/c/`→`C:/` 만 처리하고 `/tmp/…` 를 `C:/…` 와 맞추는 분기가 없다. 시뮬레이션에서 ROOT=MSYS 표기·fp=`C:/…` 표기를 주면 수정 전 훅이 allow(공허 통과)를 재현했다. 단 실제 Windows 의 MSYS 변환 동작은 Mac 에서 확정 못 함.
