# FIX-019 · 같은 질문에 답이 동시에 두 번 와도 재개는 한 번만 돈다

발견: 2026-10-05 · 복기 자료 작성 중 코드 관찰 → 테스트 방식 점검 2번 항목(메인 세션 grep 확인) | Refs: FIX-019 P5-loop S3.4 D2 원칙1

## 증상

`app/tools/questions.py::answer_question`(237행~)은 `ctx.session.get(PendingQuestion, question_id)` 로 **잠금 없이** 읽고, `question_status()` 로 "이미 답했나" 를 본 뒤 `answer`·`answered_at` 을 쓴다. 두 요청이 거의 동시에 오면(칩 두 번 클릭·재시도·탭 두 개) 둘 다 `answered_at IS NULL` 을 읽고 둘 다 통과한다 → `POST /answers/{id}` 가 저장된 context 로 **루프 재개를 두 번** 돈다. 순차로 다시 보내면 `already_answered`(409)로 막히므로 "재개 최대 1회" 는 **순차 요청에만** 성립한다.

피해: 재개가 두 번 돌면 같은 사건·일정이 두 번 기록되거나, 사용자가 서로 다른 칩을 눌렀다면 **두 답이 모두 반영**될 수 있다(예: identity 질문에 "같은 사람"·"다른 사람" — 오병합 방지 장치인 ask_user 를 우회하는 경로, 원칙1). 재현 테스트는 없다(동시성 테스트는 `SKIP LOCKED` 1건뿐).

## 원인

조회와 갱신 사이에 잠금이 없다. PostgreSQL 기본 격리 수준(READ COMMITTED)에서 두 트랜잭션은 같은 행의 옛 버전을 각각 읽는다.
