## 원인

- `tests/test_er_pipeline.py` 782행이 `_row_counts()`(73행)로 **DB 전체**의 `pending_questions` 행 수를 세고 `== 0` 을 단언한다. 이 테스트의 뜻은 "`resolve()` 만 부르면 질문이 새로 생기지 않는다"(결정4 — 부수효과 없음)인데, 단언은 "DB 에 질문이 하나도 없다"로 더 강하다.
- P5-loop 01-plan 의 "7행 명령"(판정 표 7·22행)은 확인용 세션(`judge-row7-*`)의 행을 `s.commit()` 으로 개발 DB 에 **실제로 남긴다**(01-plan 182행). 그 뒤로 DB 전체 개수는 0 이 아니게 되어 위 단언이 실패한다.
- 같은 파일의 다른 `_row_counts()` 사용(157·162행, 807·812행)은 전후 비교라 영향이 없다. 절대 개수를 단언하는 곳은 782행 한 곳뿐이다(`grep -n "_row_counts(" -A2 tests/test_er_pipeline.py`).

## 수정안 (파일 · 방식 · 회귀 테스트)

- 파일: `tests/test_er_pipeline.py` 한 곳(782~783행). 제품 코드(`app/`)는 건드리지 않는다.
- 방식: `resolve()` 호출 **전** 개수를 재고, 호출 **후** 개수가 같음을 단언한다(같은 파일 807·812행과 같은 전후 비교 방식). 테스트 이름·docstring·검증 대상은 그대로다.
- 회귀 테스트(완료 판정 명령):
