# FIX-018 · 작업 브랜치 dev2 에도 CI 를 돌린다

발견: 2026-10-05 · 테스트 방식 점검(메인 세션, 사용자 요청) | Refs: FIX-018 L-001 FIX-006 원칙8

## 증상

`.github/workflows/tests.yml` 의 트리거는 `on.push.branches: [main, dev]` 와 `pull_request` 뿐이다. L-001 개정(2026-09-29)으로 모든 커밋이 `dev2` 에 쌓이게 됐는데 워크플로는 그대로라, **실제 작업 브랜치에서는 CI 가 한 번도 돌지 않는다.**

`gh run list --limit 5`(2026-10-05) — 마지막 실행은 2026-10-02 11:39 `dev` 의 `f9500fe`(P6-briefing 완료 처리). 그 뒤 `dev2` 에 올라간 `608694b`(FIX-017) · `fa5802d`·`a69af80`(P7 계획) · `85393e0`(U1) · `6c98516`(U2) · `47adb1e` · `f256259`(U3) 는 CI 0회. 테스트는 로컬 실행과 메인 세션 재확인에만 기대고, CI 는 `dev` 승격 때 처음 돈다.

피해: 로컬과 CI 환경 차이(Python 3.14 vs 3.13, 깨끗한 DB, Linux)로만 드러나는 실패가 승격 직전까지 숨는다. "기계 검증" 을 원칙으로 하는 하네스에서 기계 검증이 빠진 구간이 가장 긴 구간이다.

## 원인

L-001 개정(dev2 도입) 때 브랜치 규칙을 훅(`safety-guard.sh`)·스킬·CLAUDE.md 에는 반영했지만 `.github/workflows/tests.yml` 은 갱신 대상에 없었다(2026-09-25 `1e4afb4` 이후 미수정).

## 수정안 (파일 · 방식 · 회귀 테스트)

| # | 파일 · 방식 | 완료 판정 명령 | 기대 출력 |
|---|---|---|---|
| 1 | `.github/workflows/tests.yml` — `on.push.branches` 에 `dev2` 추가 | `grep -n "branches" .github/workflows/tests.yml` | `[main, dev, dev2]` |
| 2 | 같은 파일 — `concurrency: { group: tests-${{ github.ref }}, cancel-in-progress: true }` 추가. dev2 는 커밋마다 푸시하므로 연달아 밀면 옛 실행을 취소해 최신 커밋만 끝까지 돈다 | 같은 파일 grep `concurrency` | 1줄 이상 |
| 3 | 이 FIX 커밋을 `git push origin dev2` 한 뒤 CI 결과 확인 | `gh run list --branch dev2 --limit 1` | 이 커밋 제목, `completed success` |

- 다른 단계(Python 버전, skip=실패 규칙, DB 서비스)는 바꾸지 않는다 — Python 버전 정렬은 테스트 점검 5번 항목으로 별도 FIX.
- 저장소는 PUBLIC 이라 Actions 사용 시간 비용은 없다(`gh repo view` → `"visibility":"PUBLIC"`).
- 제품 코드(`app/`)·테스트 무변경.

## 기획서 정합성
수정이 원칙·D·S 를 바꾸는가? — 아니다. 원칙8(재현 가능한 평가·검증)을 더 넓게 지키는 운영 변경이고, L-001 의 브랜치 역할(dev2 = 작업·실험)을 바꾸지 않는다. 결정 카드·CR 불필요.

검증: 통과(정합성 점검표 1~8 — 범위·원칙·D·S 무관, 의존 순서 무관, 보안: 비밀 없음 · 외부 전송은 기존 GitHub Actions 와 같음)
승인: 사용자 (2026-10-05) — dev2 트리거 + concurrency, U4 커밋 직후 적용

## 결과 (커밋 해시 · 테스트)

- 1·2단계: `.github/workflows/tests.yml` — `branches: [main, dev, dev2]`, `concurrency: tests-${{ github.ref }}` · `cancel-in-progress: true`. YAML 파싱 확인(`yaml.safe_load` → `{'branches': ['main', 'dev', 'dev2']}`).
