# FIX-012 · DB 기본 포트를 5433 으로 맞춘다

발견: 2026-09-29 · FIX-011 로 구현 검증을 고치다가, 두 기기 모두 5433 을 쓴다는 것이 확인되어 | Refs: FIX-012 FIX-011 FIX-006 security

## 증상

`app/config.py` 의 `DEFAULT_PORT` 가 `"5432"` 인데, 이 저장소의 `docker-compose` 로 띄우는 개발·테스트용 PostgreSQL 은 호스트 **5433** 에 매핑된다. 그래서 포트를 따로 주지 않으면 테스트가 5432 로 붙으려다 실패하고 DB 테스트가 통째로 건너뛰어진다.

FIX-011 에서 이 상황을 실제로 관측했다. `verify-impl.sh` 를 그냥 돌리면 `1215 passed, 309 skipped` 가 나왔고, 건너뛴 사유는 전부 `local PostgreSQL not reachable … port 5432 … Connection refused` 였다.

## 원인

기본값이 표준 PostgreSQL 포트(5432)로 잡혀 있었다. 5432 는 다른 프로젝트가 쓰고 있어 이 저장소는 5433 으로 피했는데, 코드의 기본값은 따라가지 않았다.

FIX-011 에서는 이 문제를 **실행 방법**으로 풀었다(A안 — 환경 파일을 셸에 올린 뒤 검증을 돌린다). 그때 기본값을 바꾸는 안(C안)을 접은 이유는 "다른 기기가 5432 를 쓰면 그쪽이 깨진다" 였는데, **사용자가 Windows 기기도 5433 이라고 확인해 주어 그 전제가 사라졌다.**

## 수정안 (파일 · 방식 · 회귀 테스트)

`app/config.py` 의 `DEFAULT_PORT` 를 `"5433"` 으로 바꾼다. 함께 `.env.example` 의 `POSTGRES_PORT` 와 `DATABASE_URL` 도 5433 으로 맞춘다(사용자가 이미 고쳐 두었다 — 이 FIX 가 그 변경의 근거를 기록한다).

**CI 는 영향을 받지 않는다.** `.github/workflows/tests.yml` 은 서비스 컨테이너를 `5432:5432` 로 띄우고 `DATABASE_URL` 을 직접 준다. `app/config.py` 의 해석 순서상 `DATABASE_URL` 이 있으면 그 값이 우선이고 `DEFAULT_PORT` 는 쓰이지 않는다(`resolve_connection` 의 `if database_url:` 갈래).

**A안(환경 파일을 올려 검증)은 그대로 둔다.** 기본값이 맞아도 `DATABASE_URL`·API 키 같은 다른 값은 여전히 필요하고, FIX-011 이 넣은 "DB 미연결 skip 은 FAIL" 규칙도 안전망으로 남는다. 이 FIX 는 흔한 실수 하나를 줄일 뿐 그 규칙을 대체하지 않는다.

## 기획서 정합성

수정이 원칙·D·S 를 바꾸는가? **바꾸지 않는다.** 바뀌는 것은 연결 기본값 하나이고 스키마·툴 시그니처·임계치는 그대로다. FIX-006(테스트는 전용 DB `relationship_test` 에만 붙는다)도 영향을 받지 않는다 — 포트만 바뀌고 DB 이름 규칙은 그대로다. 값은 비밀이 아니므로 `.env.example` 에 적어도 security §1 에 걸리지 않는다.

### 검토하고 보류한 것 — 코드가 환경 파일을 직접 읽게 할 것인가 (사용자 제안, 2026-09-29)

사용자가 "이런 구조가 환경변수를 가져오도록 해야 추후 코드 관리에 유리한 것 아닌가, 보안성을 가지고" 라고 물었다. 타당한 지적이다. 오늘 하루에 같은 종류의 어긋남이 두 번 났고(FIX-011 의 DB 미연결 skip, 이 FIX 의 기본 포트), 원인은 **값이 코드 기본값과 환경 파일 두 곳에 흩어져 있다**는 것이다.

용어를 정리하면, `.env` 는 그 자체로 환경변수가 아니라 그냥 텍스트 파일이다. 누군가 그 내용을 `os.environ` 으로 옮겨 담아야 코드가 본다. 지금은 **셸이** 옮긴다(`set -a; . ./.env; set +a` — A안). 제안은 **앱이** 시작할 때 `load_dotenv(override=False)` 로 옮기자는 것이다(B안). 어느 쪽이든 `app/config.py` 는 지금처럼 `os.environ` 만 읽는다 — 바뀌는 것은 옮겨 담는 주체뿐이다.

보안 설계는 이렇게 잡았다. `override=False` 로 두면 이미 `os.environ` 에 있는 값을 덮지 않으므로, 배포 서버에서 SSM Parameter Store 가 넣은 운영 값이 항상 이긴다. 파일을 읽는 주체는 파이썬 프로세스이지 에이전트가 아니므로 훅의 비밀 파일 차단(security §1)은 그대로다. 값은 로그에 찍지 않는다(`resolve_connection` 이 이미 변수 이름만 경고한다). 그리고 **테스트는 읽지 않는다** — 개발자의 파일에 따라 결과가 달라지면 증거 파일의 "1524 passed" 가 기기마다 다른 뜻이 되고, 원칙8(재현 가능)과 FIX-006(테스트 DB 격리)이 무너진다.

**그런데 사용자가 "앱이 시작할 때라는 건 테스트할 때를 의미하는 거지?" 라고 되물어 설계의 구멍이 드러났다.** `tests/test_api.py`·`test_api_chat.py`·`test_api_answers_resume.py` 세 개가 `app.main` 을 직접 import 한다. `app/main.py` 에 `load_dotenv()` 를 두면 테스트가 그 모듈을 불러오는 순간 함께 실행되어, "테스트는 읽지 않는다" 가 성립하지 않는다. 제대로 분리하려면 실행 전용 진입점(`app/run.py`)을 따로 만들고 서버 기동 명령을 `uvicorn app.run:app` 으로 바꿔야 한다.

**결정: A안을 유지한다(사용자 2026-09-29).** 이유는 세 가지다. 첫째, 오늘 문제의 실제 원인은 "파일을 안 읽어서" 가 아니라 기본값이 실제와 어긋나서였고 그건 이 FIX 로 닫혔다 — 이제 환경변수 없이도 `1524 passed, skip 0` 이다. 둘째, B안은 진입점이 둘로 늘어 실행법을 새로 외워야 하는 비용이 있다. 셋째, 진입점 정리는 배포를 실제로 꾸리는 **P9(AWS)** 에서 어차피 하게 되므로 그때 함께 하는 것이 자연스럽다. `lessons/CANDIDATES.md` 에 **C-8** 로 올려 두었다.

곁들여 고친 것: `tests/test_config.py` 가 기본 포트를 글자 그대로 단언하고 있어 함께 5433 으로 바꿨다. 기호(`DEFAULT_PORT`) 대신 글자를 두는 쪽을 유지했다 — 기본값이 조용히 바뀌면 포트를 주지 않은 실행이 전부 엉뚱해지므로 그 변화를 테스트가 잡아야 한다. `tests/test_db_check.py` 와 `tests/conftest.py` 의 설명 문구도 5433 으로 맞췄다.
