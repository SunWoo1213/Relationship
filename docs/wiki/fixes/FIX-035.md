# FIX-035 · identity 질문에 "다른 사람이에요" 라고 답하면 발화가 통째로 버려진다

발견: 2026-10-15 · P8-frontend U10 사람 점검(실서버·실 LLM·데스크톱 Chrome 156.0.8078.35) | Refs: P8-frontend P5-loop D1 D10 S3.3 S3.4 원칙1 원칙2 원칙9

## 증상

사용자 발화(개발 DB `relationship`, 세션 `1e3d6ea8-91f8-442b-a63e-4d39de19018e`):

`agent_traces` (같은 세션): q7 의 `er_resolve`(id 283) 출력 `"band": "identity", "band_by_threshold": "new_person", "forced_reason": "no_matched"` → 답 뒤 `answer_question`(288) → `loop_resume`(289) → `loop_resolve_done`(290) → `loop_record`(291) → `loop_turn`(292). **`create_person`·`add_event` 0회**, 화면 응답 "이번 발화에서는 새로 기억한 것이 없어요." q5 도 같다. q6("민수" 선택)은 `update_person`·`add_event` 가 정상 실행됐다.

두 가지 문제:
1. 사용자가 "다른 사람"이라고 분명히 답했는데 그 인물과 점심·이사 사건이 함께 사라진다. 다시 물어 볼 길도 없다.
2. 후보가 1명이면 질문이 "민수 중 한 분이 맞으실까요?"처럼 어색하다.

## 원인

1. `app/agent/loop.py:1337-1348` `resume_turn()` identity 분기 — 답이 `candidate_ids` 밖이면 `_drop_calls_for_mention(pending_calls, mention)`(1224-1229행)으로 그 언급의 보류 제안을 모두 버리고 끝난다. 이는 P5-loop 01-plan U7(94행) "부정 답 → 아무것도 만들지 않고 그 사실을 응답·trace(`loop_resume`)에 남긴다" 그대로의 **의도된 동작**이다. 그러나 identity 거절은 "이 후보가 아니다"일 뿐 "기억하지 마라"가 아니다. 그 뒤 새 인물로 기억할지 묻는 경로가 기획서·S·D 어디에도 정해져 있지 않다(S3.4 "칩 선택 → 재개 → 후속 툴", D1 은 new_person 질문에만 해당). 테스트도 없다(`tests/test_api_answers_resume.py` 에 identity 거절 케이스 없음 — new_person 거절 `test_answers_resume_new_person_reject_creates_nothing` 264-284행만 있음).
2. `app/er/pipeline.py:209-210` — `names_text = "/".join(names)` 뒤에 "중 한 분이" 를 후보 수와 관계없이 붙인다.

## 수정안 (파일 · 방식 · 회귀 테스트)

**(가) identity 거절 → 같은 언급의 new_person 질문으로 잇는다**(`app/agent/loop.py` `resume_turn`)
- 답이 identity 후보 밖이면 보류 제안을 버리지 않는다. 같은 `mention` 으로 **new_person 질문을 새로 낸다.** 모양은 지금 루프가 내는 new_person 질문과 같다(`_extend_for_ask` → `_extend_new_person_payload`).
  - 질문: `"<mention>"을(를) 새 인물로 기억해둘까요?`
  - 칩: `NEW_PERSON_TAG_OPTIONS` 5개 + `"아니요"`
  - 재개 재료(`PendingResume`)에는 원래 `pending_calls`·`hints` 를 그대로 싣는다.
- 그리고 그 자리에서 재개 턴을 끝낸다. 01-plan U7 의 "재개 중 또 되물으면 그 자리에서 끝낸다" 와 같은 규칙이다.
- **ER 을 다시 돌리지 않는다.** 다시 돌리면 같은 identity 질문이 또 나온다. 사용자가 방금 "다른 사람"이라고 했으므로 band 는 `new_person` 으로 정한다.
- 근거 기록(원칙9): 이 전환을 `loop_resume` trace `output` 에 `identity_rejected: true`·`followup_question_id` 로 남긴다.
- 이어진 new_person 질문에 답하면 기존 경로를 그대로 탄다.
  - 태그 칩 → `create_person`(D1 "승인 시에만") → 남은 보류 제안(점심 `add_event` 등) 실행
  - "아니요" → 지금처럼 0회
- 오병합 위험 없음: 자동 병합·자동 생성이 없다(원칙1·D1). 사람이 두 번 답해야 만들어진다.

**(나) 후보 1명일 때 질문 문구**(`app/er/pipeline.py`)
- 후보 1명: `"<mention>" -- <이름> 님이 맞으실까요?`
- 후보 2명 이상: 지금 문구 그대로(`A/B 중 한 분이 맞으실까요?`)
- 칩(options)·`candidate_ids`·`affirmative_options` 는 바꾸지 않는다.

**회귀 테스트**
- `tests/test_api_answers_resume.py`(또는 `tests/test_agent_loop.py`)
  - identity 거절 → 응답 `pending_question.kind == "new_person"`, options == 태그 5 + "아니요", 인물·사건 행 수 변화 0
  - 이어서 "직장으로 기억할게요" → `persons` +1(`relation_tag="직장"`, display_name = mention), 원래 발화의 `add_event` 실행(`events` +1)
  - 이어서 "아니요" → 0회
  - `loop_resume` trace 에 `identity_rejected`·`followup_question_id`
- `tests/test_er_pipeline.py`: 후보 1명 문구 · 2명 이상 문구 각 값 단언
- 변이(구현자·verifier): 거절 분기를 옛 drop 으로 되돌리면 실패, 후속 질문 kind 를 identity 로 바꾸면 실패, 1명 문구를 옛 문구로 되돌리면 실패
