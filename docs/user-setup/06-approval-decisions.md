# 06 · 하네스가 사용자에게 묻는 승인·결정 (무엇을 어떻게 답하는가)

에이전트는 아래 순간마다 멈추고 AskUserQuestion 으로 묻는다. 답하기 전에 볼 것과 선택지의 뜻이다.

| 순간 | 묻는 것 | 선택지 | 답하기 전에 볼 것 |
|------|--------|--------|------------------|
| 세션 시작·재개 | 중단된 작업 목록 우선순위 (`/devlog resume`) | 이어서 완료 / 보류 / 폐기 | HANDOFF "진행 중", `git status` 요약 |
| 단계 시작(L-004) | architect / backend-agent / eval-agent / verifier 를 띄워도 되는가 | 승인 / 다른 순서 / 보류 | 무엇을 누구에게, 예상 산출물 경로 |
| 계획 승인 | 01-plan + verifier 점검표 결과 | 승인 / 수정 요청 / 보류 | 작업 단위·수용 기준·**사용자 결정 후보 A~**(여기서 정한 것이 구현 규칙이 된다) |
| 완료 승인 | 04-review 판정 | 승인 / 수정 / 보류 | 필수 소견 0인지, verify-impl FAIL 0 인지, 다음 패키지 인계 |
| 커밋(/commit) | 초안(변경·이유·정합성·검증·Refs) | 커밋 / 커밋+푸시 / 초안 수정 / 취소 | 한 커밋 = 한 의도인지 |
| dev 푸시 뒤(L-003) | main 승격 여부 | 승격 / 수정 필요 / 보류 | 실서버 검증 근거(`SERVER-CHECKLIST.md`) 또는 로컬 검증 근거(app/ 무변경 등) |
| 기획서 변경(/devlog change) | CR 선택지·비용·위험 | 수용 / 부분 / 거절 | 영향 커밋 목록(태그 grep) |
| 3회 재검증 후에도 열린 소견 | 어떻게 할지 | FIX / CR / 보류 | 원칙8 — 재시도 남발 금지 |

## 답할 때 규칙
- "Other" 로 자유 답변을 쓸 수 있다. 결정 후보 A~ 에는 근거 한 줄을 남기면 01-plan "검수 후 결정" 블록에 그대로 들어간다.
- 승인 마커는 에이전트가 `approve-commit.sh` 로 만든다. 사용자가 직접 만들 일은 없다.
- 푸시는 `dev` 만. `main` 은 승격 질문에 "승격"이라고 답할 때만 올라간다.
- 사용자가 직접 실행해야 하는 명령(키 필요·인터랙티브 로그인)은 프롬프트에 `! <명령>` 으로 치면 출력이 대화에 들어온다 — **키 값은 명령줄에 쓰지 않는다**(01 카드).
- 세션이 길어지면 에이전트가 HANDOFF 를 갱신하고 멈출 수 있다. 다음 세션 첫 질문은 항상 "중단된 작업을 어떻게 할까"다.
