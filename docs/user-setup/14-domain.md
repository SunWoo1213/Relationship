# 14 · 도메인 구매와 적용 절차

> 사용자 요청(2026-11-16): "도메인을 구매해서 적용하는 것까지 하고싶으니까 그 절차를 문서로 정리해줘".
> 지금 배포 주소는 `https://54-79-202-221.sslip.io`(고정 IP `54.79.202.221`, 시드니 EC2 1대, Caddy 자동 HTTPS)다. 이 문서는 그 주소를 **내가 산 도메인**으로 바꾸는 순서다.
> **코드는 바꾸지 않는다.** 호스트명은 서버 `.env` 의 `SITE_ADDRESS` 한 줄로 정해진다(`Caddyfile` 첫 줄 `{$SITE_ADDRESS}`).
> 구매·결제·DNS 콘솔·서버 `.env` 수정은 **사용자만** 할 수 있다. 에이전트는 바깥 확인(`dig`, 본문 없는 조회)만 한다.
> 값(계정·결제 정보·비밀번호)은 이 문서에 쓰지 않는다. 도메인 이름은 비밀이 아니므로 정해지면 에이전트에 알려 준다.

## 0. 먼저 정할 것

| 정할 것 | 권장 | 이유 |
|---|---|---|
| 언제 바꾸나 | **11-17(화) 오전까지**, 늦으면 평가(11-18) 뒤 | DNS 전파와 인증서 발급에 시간이 걸릴 수 있다. 평가 직전에 주소를 바꾸면 되돌릴 시간이 없다 |
| 어떤 이름 | 짧은 `.com`·`.kr`·`.dev` 등 하나. 서비스는 `app.<도메인>` 같은 **하위 이름** 또는 도메인 자체(루트) 중 하나 | 하위 이름을 쓰면 나중에 루트를 다른 용도로 쓸 수 있다 |
| 어디서 사나 | DNS 관리 화면을 바로 쓸 수 있는 등록기관(가비아·후이즈·Cloudflare Registrar·AWS Route 53 등) | A 레코드 1개만 넣으면 되므로 어느 곳이든 된다. 가격은 확장자·등록기관마다 다르니 결제 화면에서 **첫해 가격과 갱신 가격**을 둘 다 확인한다 |
| 자동 갱신 | **끈다**(계속 쓸 생각이 없으면) | 서버는 11-19 에 종료한다. 도메인은 1년 단위라 자동 갱신이 켜져 있으면 내년에 또 결제된다 |

알아 둘 것 — 주소를 바꾸면 생기는 일:
- **계정·기억 데이터는 그대로다.** DB 는 건드리지 않는다.
- **모든 사용자가 새 주소에서 다시 로그인해야 한다.** 로그인 쿠키는 주소(호스트)에 묶여 있다.
- **알림 구독은 새 주소에서 "알림 받기" 를 다시 눌러야 한다.** 브라우저 알림 권한과 구독은 주소 단위다.
- **옛 주소(`…sslip.io`)는 더 이상 열리지 않는다**(Caddy 가 `SITE_ADDRESS` 의 이름만 받는다). 시연 자료·발표 자료에 적은 주소를 함께 바꾼다.
- 좋아지는 점: `sslip.io` 는 누구나 같은 "사이트" 로 취급되는 주소를 만들 수 있는 이름이라(P9b 계획 검증 F-7) 요청 출처 검사를 따로 뒀다. 내 도메인에서는 그 걱정이 줄어든다(검사는 그대로 둔다).

## 1. 도메인 구매 (사용자)

- [ ] **1-1** 등록기관에서 원하는 이름을 검색해 구매한다. 결제 화면에서 첫해 가격·갱신 가격·자동 갱신 여부를 확인한다.
- [ ] **1-2** 구매 뒤 **DNS 관리(레코드 편집) 화면**에 들어갈 수 있는지 확인한다. 등록기관이 기본 네임서버를 제공하면 그대로 쓴다(네임서버를 다른 곳으로 옮길 필요 없다).
- [ ] **1-3** 일부 확장자(`.kr` 등)는 등록자 정보 확인 메일이 온다. 메일의 확인을 누르지 않으면 며칠 뒤 도메인이 정지될 수 있으니 바로 처리한다.
- [ ] **1-4** 정한 호스트명을 에이전트에 알린다(예: `app.example.com`). 아래에서는 `<호스트명>` 으로 쓴다.

## 2. DNS 레코드 넣기 (사용자)

- [ ] **2-1** DNS 관리 화면에서 **A 레코드** 1개를 만든다.

| 항목 | 값 |
|---|---|
| 종류 | `A` |
| 이름(호스트) | 하위 이름을 쓰면 그 부분만(예: `app`), 루트를 쓰면 `@` |
| 값(IP) | `54.79.202.221` |
| TTL | `300`(5분) — 선택할 수 없으면 가장 짧은 값 |

- [ ] **2-2** `AAAA`(IPv6) 레코드는 만들지 않는다 — 서버에 IPv6 주소가 없다. 등록기관이 기본으로 넣어 둔 주차(parking) 용 `A`·`AAAA`·`CNAME` 레코드가 같은 이름에 있으면 지운다.
- [ ] **2-3** Cloudflare 를 쓴다면 그 레코드의 프록시(주황 구름)를 **끈다(DNS only)**. 켜 두면 Caddy 가 인증서를 받지 못하거나 알림·쿠키 동작이 달라진다.
- [ ] **2-4** 전파 확인(내 컴퓨터 터미널): `dig +short <호스트명>` → `54.79.202.221` 한 줄이 나올 때까지 기다린다(보통 몇 분, 길면 수십 분). **이 값이 나오기 전에 3단계로 가지 않는다** — 이름이 서버를 가리키지 않으면 인증서 발급이 실패하고, 여러 번 실패하면 발급 기관이 한동안 발급을 막는다.

## 3. 서버에 적용 (사용자, SSH)

- [ ] **3-1** 접속: `ssh -i ~/.ssh/relationship-deploy ubuntu@54.79.202.221`
- [ ] **3-2** (권장) 지금 설정 백업: `cd ~/Relationship && cp .env .env.before-domain`
- [ ] **3-3** `.env` 에서 `SITE_ADDRESS` 줄만 바꾼다: `nano .env` → `SITE_ADDRESS=<호스트명>` (앞에 `https://` 없이, 포트 없이, 이름만). 다른 줄은 건드리지 않는다. 저장 뒤 `chmod 600 .env`.
- [ ] **3-4** 다시 띄운다(코드는 그대로이므로 빌드 없이 설정만 반영된다): `GIT_SHA=$(git rev-parse --short HEAD) docker compose -f docker-compose.prod.yml up -d`
- [ ] **3-5** 상태: `docker compose -f docker-compose.prod.yml ps` → 세 서비스 Up.
- [ ] **3-6** 인증서 발급 확인: `docker compose -f docker-compose.prod.yml logs --tail=50 caddy | grep -i "certificate obtained"` → 한 줄이 나오면 됐다. 1~2분 걸릴 수 있다. `error`·`challenge failed` 가 보이면 4단계 "안 될 때" 로.

## 4. 확인

- [ ] **4-1** (에이전트에 맡길 수 있음) 바깥 확인 — `curl -s https://<호스트명>/api/health` → `{"status":"ok","db":"up","alembic_revision":"…"}`, `curl -s -o /dev/null -w '%{http_code}' https://<호스트명>/` → `200`, `http://<호스트명>/` → `308`(HTTPS 로 넘김), 로그인 없이 `https://<호스트명>/api/persons` → `401`.
- [ ] **4-2** (사용자) 브라우저로 `https://<호스트명>` → 주소창에 자물쇠 → 로그인 화면 → 기존 계정으로 로그인 → 인물·대화 기록이 그대로인지.
- [ ] **4-3** (사용자, 알림을 쓸 때) 브리핑 화면 "알림 받기" 를 다시 누른다.
- [ ] **4-4** 에이전트에 "도메인 적용했어, `<호스트명>`" 이라고 알린다 → 에이전트가 문서(11·12·13, 점검표, 발표 자료 주소)를 새 주소로 고친다.

### 안 될 때

| 증상 | 볼 것 | 조치 |
|---|---|---|
| 브라우저에 인증서 경고 | `dig +short <호스트명>` 이 `54.79.202.221` 인가 | 아니면 2단계 레코드를 고치고 전파를 기다린 뒤 `docker compose -f docker-compose.prod.yml restart caddy` |
| caddy 로그에 `challenge failed` | 같은 이름에 다른 `A`/`AAAA`/`CNAME` 이 남아 있는지, Cloudflare 프록시가 켜져 있는지 | 지우거나 끄고 5분 뒤 `restart caddy`. **반복해서 재시작하지 않는다**(발급 제한) |
| 로그인이 안 된다 | 옛 주소(`sslip.io`)로 접속하고 있지 않은지 | 새 주소로 접속해 다시 로그인 |
| 급하게 되돌려야 한다 | — | `.env` 의 `SITE_ADDRESS` 를 `54-79-202-221.sslip.io` 로 되돌리고(또는 `cp .env.before-domain .env`) 3-4 명령 재실행. 데이터는 그대로다 |

## 5. 종료할 때 (11-19, `12-shutdown.md` 와 함께)

- [ ] **5-1** 서버를 종료(`terraform destroy`)한 뒤 DNS 의 A 레코드를 지운다 — 고정 IP 가 반납되면 그 IP 를 다른 사람이 받을 수 있다. 레코드를 남겨 두면 내 도메인이 남의 서버를 가리키게 된다.
- [ ] **5-2** 계속 쓰지 않을 도메인이면 자동 갱신이 꺼져 있는지 다시 확인한다.
- [ ] **5-3** `.env.before-domain` 은 서버와 함께 사라진다(별도 조치 없음).

## 에이전트가 할 수 없는 것 · 확인하지 못한 것

- 도메인 구매·결제, 등록기관 DNS 화면 조작, 서버 `.env` 수정과 SSH 명령 — 사용자 몫.
- 옛 주소와 새 주소를 **동시에** 열어 두는 설정(`SITE_ADDRESS` 에 이름 두 개)은 확인하지 않았다. 필요하면 에이전트가 로컬 운영 구성으로 먼저 시험한 뒤 안내한다.
- 등록기관별 화면 이름·가격·전파 시간은 곳마다 다르다. 이 문서의 화면 용어는 일반적인 이름이다.
